# 教学画面编排

目标：让学生随着口播理解概念及其关系，提高首次样段的表达质量，减少交付后返工。用本课内容作设计判断，保留用户已确认的风格与阶段边界。

## 先继承项目约定

- 先读当前工作目录的 [AGENTS.md](../../../AGENTS.md)；克隆目录若引用共同原则，也按其指向读取。下列链接均指向当前仓库，不跨目录导入原项目代码。
- 相关制作以四项规范为准：[头尾区域](../../../docs/architecture/视频头尾区域规范V0.1.md)、[背景](../../../docs/architecture/视频背景规范V0.1.md)、[字幕](../../../docs/architecture/字幕规范V0.1.md)、[章节主标题](../../../docs/architecture/章节主标题样式规范V0.1.md)。**四项规范高于本 skill 及外部 skills 的设计建议；用户另有明确指示时按其指示执行。**
- 保留已确认口播的文字、顺序、教材关系和题目事实。可以提炼屏幕教学文字，但不要改写口播或把推测补成教材结论。
- 任务范围、停止点和已通过的效果沿用 [接手说明](../../../docs/architecture/课时制作-Agent接手与协作说明V0.1.md) 与本课记录。只分析时输出分析；只安排画面时不写视频代码。制作授权不包含重做已通过片段、调整公共架构或上传 GitHub。

## 设计路径：目的 → 角色 → 层级 → 时间 → 观看

这是一条用于作判断的路径，不是五份交付文档或五个审批节点。先读本轮口播及必要的前后衔接，按需选读一个相近的 [L01 实例](references/lesson-examples.md)。在现有画面安排中用少量条目写出关键判断，已有合适安排直接复用。

### 1. 教学目的：学生此刻需要理解什么

以一个完整讲解意图组织画面，不机械按句切镜。用一句话说明学生应获得的认识或判断依据，再选择合适的表达：定义可以配边界与实例，对比需要共同参照，分类需要归属，过程需要顺序，因果需要依据，列举可以直接用清晰列表。

图形的包含、方向、距离和先后都可能传达含义；不要为布局好看而增加教材没有的层级、因果或数量关系。“出现三个卡片”只说明实现，还应说明三项之间是什么关系。

### 2. 信息角色：谁在被讲解，谁帮助解释

识别当前的**教学主体、解释材料、定位与辅助信息**，再决定哪些需要同时出现。角色随讲解变化：总图可以先是主体，展开细节时成为定位参照；比较时两侧可以共同构成主体。不是每个画面都必须凑齐这三类。

- 解释文字要有明确对应的对象；图与文字共同说明关系，避免重复铺陈或先给一段缺少参照的抽象结论。
- 标题根据职责区分：章节定位、当前问题、图内名称、局部说明无需同等突出；承担组织内容作用的标题应能被识别，不能仅凭“写在上方”完成层级。
- 字幕承载口播，内容区承载必要的教学结构与阅读材料。保留完整题面等任务所需文字，移除面向制作者的备注。

### 3. 视觉层级：把信息角色变成可感知的主次

在既有规范内，共同安排**面积、位置、字号与字重、明暗与颜色、分组与间距**，形成清楚的阅读顺序。先确定观众应先看哪里、接着看哪里，再细化边框与装饰。

- 视觉分量要对应当前教学作用和信息量。主体需要足够的存在感；相关信息通过邻近、对齐或适当连接建立关系。留白用于分隔与聚焦，不必填满，也不要让容器大小决定内容的重要性。
- 必须阅读的信息都需清晰，包括比较另一侧、图内标签和保留的参照。降低强调可以改变边框、饱和度或局部亮度，但不能以难以辨认为代价；不要靠把其余内容全部压暗来制造重点。
- 在实际背景、透明底板和常见播放尺寸下判断文字可读性，综合考虑字号、字重、前景与背景反差。颜色服务于类别、状态或强调，保持含义稳定；必要时配合文字和形状，避免只靠颜色传递关键区别。
- 风格可以克制，也可以在需要时突出。不要把“大字、亮色、有边框”等单一外观当成通用答案；整页都被加强会再次失去层级。

### 4. 时间展开：每个教学阶段都能独立理解并连接前后

安排引入、解释、转折或展开、收束等实际需要的阶段，不要求每段都有同样结构。每个有意义的中间状态都应有当时可理解的主体与关系，不能只在全部元素出现后才成立。

- 新信息出现时，先前内容按后续用途保留、降低强调或退出。保留必要参照，避免无目的的清屏等待；待讲内容可留中性结构，但不能提前给出尚未允许揭示的结论。
- 用动作表达引入、归类、关联、聚焦或承接，再决定速度与缓动。阅读、思考、比较和总结可以静止。卡片、网格、淡入、复用布局都可采用，不以动效数量或版式变化衡量质量。
- 留足实际阅读与理解时间；解释材料的出现要跟上对应论述，结论需有依据和停留。运镜只作用于需要解释的内容，保留定位线索及安全边界，不带动固定顶栏和字幕。
- 已有音频按本课时间线定位短语，区分引入与结论揭示；尚无音频则标明节奏暂定。沿用项目的帧驱动实现，API 不确定时查可用的 Remotion 官方 skill／文档，不直接搬用网页 CSS 动画。

关键安排可简记为：**口播锚点 → 学习目的 → 主体与解释材料 → 视觉主次 → 阶段变化与承接**。只记录有决策价值的内容，不要求每句填表或用户逐项确认。

### 真题的特殊约束

完整题面保持可阅读，读题和独立倒计时阶段使用中性样式；答案色、勾叉、纠错标注、知识图分类、解析标题和字幕都不能提前暗示答案。阅读焦点、选项判定、最终答案分别跟随对应口播。倒计时长度沿用本课已确认安排，不把 L01 的 3 秒推广为所有课程的硬规则。

### 5. 观看自查：从学生实际看到的结果反查设计

在本轮允许的预览范围内，结合常见播放尺寸下的关键画面和连续播放，对照口播检查。不只看最终完整画面：选择引入、信息交接、内容最密集等本段有代表性的状态；无需逐帧审查。若只看过代码或截图，明确动态与听感尚未确认。

用三个问题检查同一条设计路径：

1. **找得到吗？** 当前主体是否明确，标题、图形与解释是否各尽其职，实际阅读顺序是否符合教学目的？
2. **读得清、看得懂吗？** 必要文字在当前背景和尺寸下是否可辨认，信息分组和关系是否准确，解释是否有对应对象？
3. **跟得上吗？** 重点转移、中间状态和段落承接是否连贯，有无过早揭示、无意义等待或来不及理解的变化？

问题出现时，沿“目的—角色—层级—时间”找原因，先修正造成问题的决定，再调整受影响的呈现；不要习惯性用加字、加框、加动画解决所有问题。核对四项规范与真题约束后，处理本轮范围内的明确缺陷。材料冲突、关键选择或环境障碍及时反馈；达到本段目的与约定交付标准即停止，不扩展成自动评审系统或无限修饰循环。

完成本轮样段和必要自查后，按原有节点反馈“完成什么、在哪里看、表达设计是什么、尚未确认什么”，等待约定的用户审核。Skill 不代替用户验收，也不默认要求另一位 agent 每段复审。
