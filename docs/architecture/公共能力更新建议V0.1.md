## 2. 完善默认值、参数覆盖和局部替换

已有接口直接复用，需要完善的接口按实际需求支持：

- 有公共默认值的可选参数可以省略，课程需要时可以覆盖。

- 局部表现需要变化时，开放对应内容或渲染部分的替换方式。

必填输入仍按实际接口提供，不把所有参数都改成可选。“可插拔”通过现有组件与参数机制实现，不另建复杂继承体系；公共默认值应符合现行规范。

## 5. 完善可按组执行的 GPU 命令

复用已有脚本与执行入口，按实际需要补充课时、分组或音频段选择参数，复用已有结果，减少每节课重复编写专用脚本。现有命令支持范围以索引为准。

命令准备、用户执行 GPU 步骤和结果核对按[AI互动流程总结](AI互动流程总结V0.1.md)第三节协作。步骤是否合并取决于实际依赖，不预先要求合成一个大命令；不能照搬其他项目的专用路径和参数。

按组配音的公共入口是 [run-group-audio.ts](../../scripts/run-group-audio.ts)。调用者传入 `--workspace=workspaces/<课>/<组>` 这类目录；省略模式时使用 CUDA。参数、输入和限制见[公共能力索引](公共能力索引V0.1.md)第七节。

- 已实现：同一命令按给定工作目录读取 `storyboard-ir.json` 并调用 `runAudioEngine()`，换组只需更换工作目录。
- 已检查：类型检查与参数回归通过，覆盖隔离目录上的错误输入、dry-run、synthetic 覆盖保护及显式 `--mode` 缺少值时拒绝执行；省略 `--mode` 时仍默认 CUDA。这些检查没有运行 GPU。
- 已完成 CUDA 缓存复用核对：用户在隔离目录 `/tmp/group-audio-cuda-check` 执行默认 CUDA 入口，日志为 `mode=cuda`，TTS 与对齐均为 `cached=True`，用时 0.8 秒；`audio-timeline.json` 的 `engineInfo.device` 为 `cuda`，WAV 与 SRT 留在该目录。正式课目录没有被这次命令改写。
- 尚未实测：`cached=False` 的全新 GPU 合成，以及 `--mode=cpu`。上述核对复用了相同口播的已有缓存，只证明命令接线与缓存复用正常，不代表新配音质量已通过审核。

## 6. 调整双版本导出，减少重复渲染（公共合成已实现）

已新增公共入口 `scripts/compose-lesson.mjs`：复用一次渲染得到的干净视频，以及同版整轨 WAV 和字幕数据，生成有声字幕 MP4、双声道 WAV、SRT 与媒体信息 JSON。字幕复用现有公共组件，视频由 CUDA / NVENC 合成和编码，原始干净版保留。参数、输入要求与整课／样段命令统一见[公共能力索引](公共能力索引V0.1.md)第九节。

公共合成入口此前的代码检查和用户小样审核结论继续沿用，各课正式交付仍按实际产物检查与视听验收；不要求每课重复性能校准，也不据此承诺固定提速幅度。有声版仍需重新编码，节省的是教学组件、布局和动画的再次计算。

`npm run render` 已通过 [deliverCompiledLesson](../../src/pipeline/4-render/dual-delivery.ts) 接入“一次干净版 → `composeLesson`”，支持复用干净版及同范围的样段音频、字幕。直接调用 `render-lesson.mjs` 仍只导出指定的一版；独立课时和已有包装脚本可显式选择本课干净版，再调用公共合成。已烧录字幕的成片不能恢复为干净版。音频与字幕沿用原始数据，不从有声 MP4 反向提取作为交付源。

## 8. 将参考案例整理为完整公共示例

当前状态：讲义已通过用户审核；四种题卡的完整公共示例已通过用户视觉审核；其他示例仍按优先级待迁移。

### 8.1 目标与边界

每项需要演示的公共能力保留一个明确的标准示例。说明、示例代码、必要数据、配套素材和代表性成果集中组织，读者从同一个目录即可理解并运行，不必到不同课程的源码、工作区和交付目录拼凑材料。四种题卡可以作为同一个题卡示例的四个变体，不要求每种变体单独建立一套工程。

规范说明通用要求，公共能力索引说明实际接口，示例展示如何调用。公共实现继续留在现有 `src`、`scripts` 等目录，示例直接调用；课时专用内容、实际音频时序和已确认成果仍在各课维护。

“一个标准示例”指每项能力有一个维护入口，不是把各课工作区合并或删到只剩一个。示例可保留必要的教材或课程出处，但理解与运行不能依赖对应旧课仍在本机。

### 8.2 目标目录与依赖要求

采用唯一公共示例目录 `src/examples/<能力名>/`，统一收纳说明与实现。下列是组织约定；[讲义示例](../../src/examples/handout/README.md)与[题卡示例](../../src/examples/quiz/README.md)已具备可运行入口，其他能力按实际需要创建文件，不预建空目录。

```text
src/examples/
  README.md                 示例入口与可用状态
  <能力名>/
    README.md               用途、必要环境、运行方式、预期结果
    示例入口与代码           调用现有公共组件或方法
    data/                   最小题目、时序、选帧等示例输入
    assets/                 运行所需的小规模图片、音频或视频
    reference/              代表性效果图、PDF 等参考成果
    output/                 运行生成的派生记录、配图与 PDF（不手工维护）
```

- 固定示例数据和必要素材在本例内保留，运行时不读取具体课程的 `src/lessons/ch…`、`docs/lessons/ch…`、`workspaces/ch…`、`public/audio/ch…`、`out/ch…` 或 `deliverables/ch…`。导入公共类型、组件、工具和项目依赖不属于课程耦合。
- 沿用项目现有运行方式。确需工作区或静态资源发布位置时，使用与本例对应的专属位置，由同一个示例入口准备，并在说明中交代；这些运行副本不成为另一份手工维护源。
- 使用少量但足以说明能力的内容。讲义示例可覆盖知识页、完整中性练习页及独立解析页，不复制整课视频、全部组装记录和几十页图片。已有配图应能直接进入排版，GPU 补图作为有需要时的步骤。
- 题卡基础样式可用注明用途的演示时序；展示口播同步时，配套本例自己的短音频及对齐数据。正式课程仍使用本课实际音频锚点。
- 选帧、裁切与文字等定义只维护一份，派生记录由程序生成；输入素材与运行结果分开。讲义补截先保留完整原帧，再进行裁切与压缩。
- 必要的小素材须随示例保留，环境依赖在本例说明中写清，不能以某台机器上的旧课文件或绝对路径代替配套材料。

`src/examples/` 统一维护讲义、题卡和表格的代码、数据、素材、说明与参考成果，根目录不再保留另一套公共示例。选图、题面与解析组织、配图处理及复用边界已整理进[完整讲义示例](../../src/examples/handout/README.md)，规范和索引直接指向独立示例；新课无需读取具体课程制作记录。
