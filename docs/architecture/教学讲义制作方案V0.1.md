# 教学讲义制作方案 V0.1

更新日期：2026-11-07。适用于本项目各课时的配套 PDF 讲义制作，承接[制作流程](AI互动流程总结V0.1.md)第五步。

以本课已确认的内容、画面和样式为依据，复用 [scripts/handout.py](../../scripts/handout.py)。完整示例、环境和输入参数见 [src/examples/handout/](../../src/examples/handout/README.md)。

## 一、制作依据与准备

开始前核对：

- 已确认的口播稿、分镜、分组审核结论，以及教材和题目依据。
- 本课已有配图、页面数据和选帧记录的版本与完整性。
- 使用视频选帧或标注回看时间时，核对同版干净视频、帧率、实际时间线与整课组装偏移。

已有图片符合版本、内容和清晰度要求时直接复用；缺图再从整课干净版截帧。干净版虽无口播字幕，仍可能显示倒计时、答案或过渡状态，须检查实际画面。

发现版本冲突时先处理受影响内容。常规分页、裁切和参数调整由 Agent 自主完成。

## 二、页面内容与选帧要求

### 2.1 知识页

按讲解顺序和知识完整性确定页数。同一分镜的不同教学状态可拆页，重复表达同一内容的画面可合并。概念比较保留双方，过程保留关键起点和结果，分类保留类别与所属项目。需要前后变化才能理解时，选取多个状态或补充有材料依据的简短说明。

选帧须满足：

- 所需文字、对象和连线完整、清楚可读。
- 已结束入场、退场或交叉淡化，重点已经建立。
- 裁切保留教学内容、图例、解释和必要关系。

结合实际画面与时间线判断，不按“每镜结束前若干秒”机械选帧。

### 2.2 真题练习页与解析页

| 页面 | 内容要求 |
| --- | --- |
| 练习页 | 题干、全部选项、题目来源、题号与作答区完整；画面中性，无答案高亮、排除标记或解析提示 |
| 解析页 | 答案与依据完整，保留理解解析所需的题面或选项，提供错因与复习笔记区 |

按[题卡规范](题卡规范V0.1.md)核对实际状态：倒计时结束可能已揭晓答案，不能作为练习页的固定选帧点；答案刚亮起也不代表解析完整。必要时换选完整状态，或依据已确认口播和教材补充对应解释，不改写答案或增加未经核实的结论。

### 2.3 页面数据与选帧记录

本课维护一份页面 JSON，按公共示例的 `lesson`、`pages` 组织顺序、标题、类别、图片、裁切及解析。`selection.json` 由公共入口生成，调整输入后重新生成，不手工维护重复记录。

从整课视频截帧时，由调用方计算：

```text
整课帧 = 分组起始帧 + 分组内局部帧
视频时间（秒）= 整课帧 / fps
```

记录源视频版本与组装数据位置。需要页眉回看时间时，传入核对后的整课 `frame` 与 `lesson.fps`，或页面 `time`；纯图片讲义可省略。公共入口不读取组装记录或计算分组偏移。

## 三、版式与图片要求

### 3.1 沿用确认样式

沿用已审核的公共样式，通过 `style`、`fonts` 调整颜色、字号、边距和留白，保证正常阅读尺寸下正文与图中细字清楚。默认页眉颜色为 `style.accent = '#147984'`，定义于公共模块 `Style`。

确需更换整体版式时，先确认少量页面；常规参数调整无需重复审核公共样式。

### 3.2 配图与检查预览

- 交付图使用高质量 JPEG，按清晰度和体积调整参数；已有 PNG 可直接转换，无需重新截帧。
- 保留完整原帧，按实际教学内容裁切；已裁切图片不重复套用原帧裁切值。
- 输入素材不删除或覆盖。PDF 使用交付配图，公共入口另生成轻量 JPEG 预览用于检查；有疑问时查看清晰局部。

## 四、生成步骤与分工

按当前缺少的步骤执行：

| 步骤 | 内容 | 分工 |
| --- | --- | --- |
| 1. 核对材料 | 确认版本，盘点已有配图 | Agent |
| 2. 准备页面数据 | 确定顺序、选帧、裁切和解释 | Agent |
| 3. 获取配图 | 复用合格图片；缺图时准备 GPU 截帧命令 | Agent 准备，用户执行 GPU 截帧 |
| 4. 核对配图 | 检查完整状态与裁切范围 | Agent |
| 5. 调用公共处理 | 生成交付图、预览、PDF 和 `selection.json` | Agent |
| 6. 检查与交付 | 核对内容与实际版面，交付 PDF | Agent 检查，用户阅读验收 |

GPU 命令须包含工作目录、运行环境、输入输出路径、预期产物和需反馈的日志；失败时保留结果并定位问题，不自动改用 CPU 截帧。图片压缩、PDF 排版和页面预览由 Agent 执行。

## 五、公共处理与新课接入

公共入口提供 `build_handout()` 与 CLI，处理裁切压缩、字体换行、PDF 排版、页码和书签。新课提供自己的页面数据与图片，直接调用；仅有额外准备或转换需求时才增加本课脚本。

在项目根目录执行：

```bash
python3 scripts/handout.py --data /path/to/handout.json --assets /path/to/assets --output /path/to/handout-v1
```

使用具备 Pillow、ReportLab 和中文、符号 TTF 的 Python 3.10+。原帧裁切使用 `[宽, 高, 左, 上]`；已有裁切图可省略裁切。输入与输出目录不能相同或互相包含；默认拒绝覆盖输出，修订时指定新版本目录。

## 六、检查、交付与验收

沿用同版有效结论，只检查本次改动及受影响部分。接入新课无需重跑整套公共回归检查。

1. **内容覆盖**：页面顺序与讲解一致，重要对象、关系、分类和边界无遗漏；题目、选项、答案与依据完整。
2. **实际画面**：清晰稳定，练习中性，解析完整，裁切未丢失关键内容。
3. **PDF 版面**：查看实际渲染页面，确认无乱码、缺字、溢出、重叠、拉伸或误裁；文字提取不能代替版面检查。
4. **文件信息**：页数、页码、书签、版本及配图一致；提供回看时间时核对其位置，PDF 能正常打开。

成果放在本课 `handout/`，修订可使用版本子目录：

```text
docs/lessons/<章节>/<课时>/handout/
  配套讲义Vx.x.pdf
  selection.json
  images-jpeg/
  previews/
```

页面输入和原始素材另存，避免与输出混用。交付 PDF 链接、页数和文件大小，说明检查范围及待确认内容。只有用户明确确认后才记录为讲义审核通过，并保留已确认成果；讲义验收不改变视频审核状态。
