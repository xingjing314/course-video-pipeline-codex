## 一、定位与三条原则

字幕是**口播的书面镜像**，不是画面文案的补充。因此：

| # | 原则 | 含义 |
| :---: | :--- | :--- |
| 1 | **不改写** | 字幕文本必须与口播稿逐字一致（只做断句，不做同义替换） |
| 2 | **不跨句合并** | 断句优先跟标点走；把两句并成一行会让"读到哪"失去对应 |
| 3 | **不覆盖静音** | 音频静音段（教学停顿）没有字幕——这是设计，不是缺陷 |

第 3 条的理由：L03 的 3 秒倒计时是留给学生思考的，如果屏幕上有字，注意力会转移到"读"而不是"想"。

## 二、数据从哪来

```
narration（带标点的原文）
   +  aligned tokens（纯字符、带毫秒时间戳，不含标点）
        │
        ├─ ① 原文按标点切 clause（保留标点）
        ├─ ② 每个 clause 在 token 流里顺序查找 → 起止毫秒
        ├─ ③ clause 合并成字幕行（按标点强度与字数）
        ├─ ④ 超长行二次切分（按 ：；，、 选断点，时间按字数比例分）
        └─ ⑤ 兜底：时间严格递增、不重叠、最短 120ms
              │
              ▼
        captions[]  →  compiled-lesson.json → CaptionsOverlay
                    →  *.srt（同一份数据导出）
```

**关键**：字幕与画面用**同一份 `captions[]`**，不存在"视频一套、SRT 另一套"。

## 三、切分规则（实现即规范）

### 3.1 参数

| 参数 | 值 | 作用 |
| :--- | ---: | :--- |
| `MAX_CHARS` | 26 | 合并上限：可见字达到 26 强制断行 |
| `MIN_CHARS` | 6 | 过滤下限（实际按 `≥3` 可见字保留） |
| 强断点阈值 | 4 | 句末标点（`。！？…`）且累计 ≥4 字即可断 |
| 弱断点阈值 | 10 | 逗号顿号分号冒号（`，、；：`）且累计 ≥10 字才断 |
| 二次切分阈值 | 28 | 单行可见字 >28 触发 `splitLong` |
| 最短时长 | 120 ms | `endMs ≥ startMs + 120` |

### 3.2 断点优先级

二次切分（`splitLong`）按下列顺序找断点，找不到就**不切**（保持原样）：

```
：；  →  ，  →  、— 
```

断点取"离行中点最近"的那个；切完把紧跟的**右引号、右括号**（`”’）》」』】`）归入前一句，避免下一行以 `”` 开头。

### 3.3 收尾符号吸收

原文切 clause 时，标点后紧跟的右引号/右括号一并归入本句：

> `他说"这样不行"。` → 断成 `他说"这样不行"。` ✅
> 而不是 `他说"这样不行` / `"。` ❌

这条规则来自 L02 的一次打回：字幕出现以 `”` 开头的行。

## 四、时序规则

| 规则 | 说明 |
| :--- | :--- |
| 起点 | 取该行首字 token 的 `startMs` |
| 终点 | 取该行末字 token 的 `endMs`，且 ≥ 起点 + 120ms |
| 严格递增 | 后一条起点若早于前一条终点，强制对齐到前一条终点（不重叠） |
| 静音段 | 无 token ⇒ 无字幕；3 秒倒计时期间字幕自然为空 |
| 首条 | 通常从 0.00s 开始（实测 L01/L02/L03 均为 0.00s） |
| 末条 | 落在片尾前 0.5–0.7s，不刻意延到片尾 |

## 五、呈现规范

呈现参数（字号、内边距、底板）详见[视频头尾区域规范 §3](视频头尾区域规范V0.1.md)，此处只列与**文案长度**相关的约束：

| 项 | 值 | 依据 |
| :--- | :--- | :--- |
| 字号 / 行高 | 28px / 1.4 | 1080p 下 3 米观看可读 |
| 单行容量 | **约 54 个汉字** | 盒内可用宽 1520px ÷ 28px |
| 建议行数 | **1 行**（上限 2 行） | 2 行时盒顶 y=941，距舞台仅 41px |
| 实际最长 | 35 字 | 三课实测最大值，仍为 1 行 |

> **不要靠缩字号解决长句**。字号一改，字幕盒高度变化，舞台安全区（≤900）随之被挤压，所有已交付课程都要重验。

## 六、质量指标（实测基线）

| 指标 | L01-ds | L02 | L03 | 建议阈值 |
| :--- | ---: | ---: | ---: | :--- |
| 条数 | 143 | 240 | 266 | — |
| 平均可见字 | 14.9 | 15.2 | 14.9 | **13–17** |
| 最长可见字 | 34 | 30 | 35 | **≤ 35** |
| 最短可见字 | 4 | 4 | 3 | ≥ 3 |
| 以标点结尾 | 99% | 98% | 98% | **≥ 95%** |
| 平均时长 | 3.53 s | 3.56 s | 3.74 s | 2.5–4.5 s |
| 最短时长 | 0.72 s | 0.80 s | 0.64 s | ≥ 0.5 s |
| 最大空隙 | 2.72 s | 1.92 s | 4.59 s | ≤ 5 s（教学停顿除外） |
| 超长条（>28 字） | 1 | 2 | 5 | **占比 < 2%** |

> L03 的 4.59 s 最大空隙出现在 3 秒倒计时附近，属于**预期内**的静音，不是漏字幕。

## 七、已知问题

| # | 现象 | 原因 | 处理 |
| :---: | :--- | :--- | :--- |
| 1 | 出现 >28 字的行 | `splitLong` 找不到合法断点（整句无 `：；，、—`） | 可接受（占比 <2%）；若集中出现，说明口播稿本身句子过长，应改稿而非改字幕 |
| 2 | 某条字幕时长为 0 | 对齐器吞字，`clause` 在 token 流里找不到 | 会在兜底里被撑到 120ms；**出现即说明对齐质量有问题**，需查该场景 token |
| 3 | 字幕与画面不同步 | 画面元素用**手写帧号**而非 token 定位 | 见架构说明 D6：时间点必须由 token / `pauseDirective` 派生 |
| 4 | 静音段仍有字幕 | 把停顿做成了"画面停留"而非音频静音 | 停顿必须走 `pauseDirectives`（真静音，实测 −91 dB） |
| 5 | 字幕以 `”` 或 `）》` 开头 | 未吸收收尾符号 | 已在 `splitClauses` / `splitLong` 两处吸收，改切分逻辑时不许回退 |
| 6 | 无声版出现字幕 | `includeCaptions` 传错 | 无声版必须 `false`；头栏仍保留 |

## 八、SRT 交付格式

```
1
00:00:00,000 --> 00:00:02,320
上一节我们戴上五顶帽子，

2
00:00:02,320 --> 00:00:05,760
搞清楚了可行性研究要算哪五笔账。
```

| 项 | 规定 |
| :--- | :--- |
| 编码 | UTF-8 **无 BOM** |
| 编号 | 从 1 连续递增（与 `captions[].index` 无关，导出时重排） |
| 时间戳 | `HH:MM:SS,mmm`，逗号分隔毫秒 |
| 块结构 | 编号行 / 时间行 / 文本行 / **空行** |
| 与视频一致 | 由同一个 `captions[]` 导出，天然对齐 |

## 九、变更与回归

| 改动 | 需要重跑 | 需要重渲染 |
| :--- | :--- | :---: |
| 切分规则（标点 / 阈值） | `rebuild-l01-captions.ts` | 是 |
| 字号 / 内边距 / 底色 | 无 | 是（**全部课程**） |
| 口播文案 | IR → TTS → 镜表 → 字幕 → cue → 编译 | 是 |
| 只改画面 | 无 | 是（字幕数据不变） |

命令：

```bash
# 重算字幕（按课时）
node --experimental-strip-types scripts/rebuild-l01-captions.ts --lesson=ch07-L03-ds

# 统计基线（条数 / 均值 / 最长 / 标点结尾比例）
python3 - <<'PY'
import json,re
d=json.load(open('workspaces/ch07-L03-ds/compiled-lesson.json'))
cs=d['captions']; vis=lambda t:len(re.sub(r'[^\u4e00-\u9fa5A-Za-z0-9]','',t))
print(len(cs), round(sum(vis(c['text']) for c in cs)/len(cs),1), max(vis(c['text']) for c in cs))
PY
```
