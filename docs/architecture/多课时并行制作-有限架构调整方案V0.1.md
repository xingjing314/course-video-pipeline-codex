## 一、已确认的方向与边界

1. 项目用于个人制作、保存程序和后续重构。代码、文档、课程 JSON / SRT、字体进入 Git；配音、成片、讲义交付物和缓存保留在本地或其他备份中。
2. 以第六章 L01 已审核的表现作为参考：保留其口播、画面、字幕、倒计时、答案揭示、音画节奏和交付行为。
3. 先确认小样和关键规则，再分段制作、审核，最后组装交付。并行制作仍需及时向用户反馈。
4. 本轮只处理课时隔离、入口复用、接手说明等直接阻碍并行制作的问题。
5. 暂不统一重写第六章与第七章的制作方式，不建立任务调度平台、自动审批系统、数据库或远程制作服务，不批量重做既有课程。

以下为分阶段实施方案；已完成情况以文末记录为准，未实施阶段不代表能力已经存在或经过验证。

## 五、并行工作方式

### 同机制作

建议每个制作任务使用“独立分支 + 独立 Git worktree 工作目录”。仅建立多个分支而共用一个可写目录，不能解决互相覆盖文件的问题。不同电脑上则各自克隆仓库并使用任务分支。

- 每个目录有自己的依赖安装、课程输出、缓存和预览端口；本地忽略文件不会由 Git 自动复制，需要按课准备。
- 不同任务优先分别修改自己的课时目录。公共基础变更先单独整合，再由各任务同步，不在多个任务里各自演化同一份公共组件。
- 文稿分析、图形设计、代码制作与人工审核可以交错推进。
- 同一张 RTX 5060 Ti 16GB 上，重型 TTS、对齐和整课渲染先人工错峰执行；多目录不等于硬件资源已经隔离。本轮不开发 GPU 调度器。
- 合并代码不会带回被忽略的音频和交付物。每课通过审核时，要同时记录代码版本和对应的本地成果位置。

### 第六章 L01 的代表性对照

- 开场章节标题、一个教材图解、一道真题的读题 / 倒计时 / 答案揭示、一个跨段衔接。
- 整课参数沿用 35369 帧、1920×1080、30fps；独立字幕沿用现有整课时间线。
- 比较画面表现、语音与字幕对齐、答案出现时机，不以视频文件二进制完全相同作为标准。
- 短样段与静态核对足够排除本轮影响时，不反复导出整课；若发现组装或时序变化，再扩大验证范围并报告原因。

第六章 L02 可以作为首个新课试点候选，但具体试点内容、第二个并行任务及负责 agent 另行确定。本方案不授权立即开始制作新课。

## 七、实施顺序与停止条件

1. 用户确认本方案。
2. 完成阶段 A，保留用户已有目录迁移，形成可追溯的工作基线。
3. 逐步实施 B、C，每步完成后反馈变化及对照结果，不等到全部完成才展示。
4. 完成接手说明，在用户确认试点后进行一次独立接手和两目录验证。
5. 达到“旧课表现保持、新课样段能独立完成、两个目录互不覆盖”三个条件后，结束本轮调整，再决定扩大并行数量。

若某一公共提取需要大规模重写已确认的课内组件，或验证后画面 / 音画节奏改变，应缩小或撤回该步修改，先恢复已有行为。回退只针对本轮代码变更，不覆盖用户的新改动，不删除本地素材和成片。
