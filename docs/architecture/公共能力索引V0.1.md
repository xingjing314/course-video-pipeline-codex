## 一、使用方式与入口速查

先按教学需要查找已有能力，再通过参数覆盖、组合或现有插槽完成课时设计。只有确有功能缺口时才新增实现；课时内容和专用设计留在 `src/lessons/<章节>/<课时>/`。

公共目录中的组件不一定都支持省略参数、样式覆盖或局部替换，以实际 Props 为准。当前组合组件可从 `src/visual/kit` 导入；其他能力按下表对应模块导入。

## 二、原子图形

### 2.1 入口与配置

- 实现目录：[primitives/codex-version](../../src/visual/primitives/codex-version)。
- 注册表：[PRIMITIVE_COMPONENTS / PRIMITIVE_IDS](../../src/visual/primitives/registry.ts)，建立图元 ID 与组件的对应关系。
- 数据契约：[AtomicShapeItemSchema / PrimitiveId](../../contracts/primitives.schema.ts)。
- 配置样例：[data](../../src/visual/primitives/codex-version/data)；[samples.generated.ts](../../src/visual/primitives/codex-version/data/samples.generated.ts) 导出 `PRIMITIVE_SAMPLE_CONFIGS`，该生成文件不手改。

原子组件接收 `config` 和 `localFrame`，输出 SVG `<g>`，调用方提供外层 `<svg>`。直接导入具体组件可保留具体配置类型；按数据选择图元时，可使用 `AtomicCombo`。

**当前并没有统一的“只传少量字段就自动补齐全部配置”的图元接口。** 例如 `Rect01` 要求完整的 `Rect01Config`。可以复用现有样例或课时已确认配置，再覆盖嵌套字段；样例中的位置、颜色和动画时间属于演示配置，不等于本课的设计与时序。

### 2.3 配置覆盖示例

以下代码片段演示配置覆盖，相对导入按 `src/lessons/<章节>/<课时>/` 下的文件位置书写；实际位置不同时调整导入路径。无需为使用片段另建示例文件。

```tsx
import { useCurrentFrame } from "remotion";
import { Rect01 } from "../../../visual/primitives/codex-version/_01Rect";
import type { Rect01Config } from "../../../visual/primitives/codex-version/_01RectConfig";
import sample from "../../../visual/primitives/codex-version/data/_01-rect.json";

const config: Rect01Config = {
  ...sample,
  rect: { ...sample.rect, x: 120, y: 300, width: 480, height: 240 },
  animation: {
    ...sample.animation,
    outlineStartFrame: 0,
    fillStartFrame: 12,
  },
};

export const ShapeExample = ({ startFrame }: { startFrame: number }) => {
  const frame = useCurrentFrame();
  return (
    <svg width={1920} height={1080} viewBox="0 0 1920 1080">
      <Rect01 config={config} localFrame={frame - startFrame} />
    </svg>
  );
};
```

`startFrame` 由本课音频锚点提供，并与当前组件处于同一时间坐标。`fillStartFrame` 等是图元自身入场动画的相对时间，不替代口播定位。

## 三、组合组件、布局与动效

### 3.1 kit：可以直接组合的组件

统一从 [src/visual/kit/index.ts](../../src/visual/kit/index.ts) 导入。

| 能力 | 必填输入 | 可覆盖项与当前默认行为 |
| --- | --- | --- |
| `CardGrid` | `items`、`left`、`top` | `columns=2`、`cardWidth=540`、`cardHeight=210`、`gap=140`、`enter=1`、`stagger=false`；可传 `states` |
| `Flow` | `steps`、`left`、`top` | `nodeWidth=220`、`nodeHeight=96`、`gap=48`；`activeIndex=-1`、`doneThrough=-1`；`activeIndices` 优先于单个 `activeIndex` |
| `Scale` | `marks`、`left`、`top`、`width` | `fillTo` 默认取激活刻度位置，否则为 0；`breakAt`、`breakLabel` 可显示断层 |
| `useStepper(cuts)` | 本地帧切点数组 | 返回 `passed`、`current`、`states`、`stateOf(index)`；未开始时 `current=-1` |
| `stepStates(cuts, frame)` | 切点数组、当前帧 | `useStepper` 对应的纯计算函数；状态为 `past / current / future`，最后一步保持 `current` |
| `cueCuts(cues, action?)` | 已解析的 cue 数组 | 默认筛选 `highlight-item`，返回升序 `localFrame` |
| `useStep(cuts)` | 本地帧切点数组 | 只返回已到达的切点数量 |
| `Stagger` | `children` | `index=0`、`step=6`，按 `index × step` 帧错峰入场 |

数据类型：`CardItem` 为 `{ name, line?, tone?, tag? }`；`FlowStep` 为 `{ label, code?, sub?, tone? }`；`ScaleMark` 为 `{ at, label, active?, tone? }`，其中 `at` 使用 0–1 的相对位置。

`CardGrid` 的 `enter` 与 `stagger` 选择一种入场方式；`states` 中的 `future` 只是压暗，不会隐藏内容，不能把它当作防止答案提前出现的机制。

以下组合示例沿用上一节的通用目录层级，实际使用时按文件位置调整相对导入：

```tsx
import { CardGrid, cueCuts, useStepper } from "../../../visual/kit";
import type { ResolvedCuePoint } from "../../../../contracts/visual-props.schema";

export const CardsExample = ({ cues }: { cues: ResolvedCuePoint[] }) => {
  const steps = useStepper(cueCuts(cues));
  return (
    <CardGrid
      items={[{ name: "目标" }, { name: "行动" }, { name: "结果" }]}
      left={96}
      top={300}
      columns={3}
      cardWidth={500}
      gap={40}
      states={steps.states}
    />
  );
};
```

本例省略的卡片高度沿用默认值。cue 的顺序应对应卡片顺序；`cueCuts` 按动作筛选，不按 `targetId` 自动匹配卡片。

### 3.2 公共面板与局部标题

入口：[templates/shared.tsx](../../src/visual/templates/shared.tsx)。

| 导出 | 用法与边界 |
| --- | --- |
| `SceneShell` | `title` 必填，`subtitle / eyebrow / children` 可选；提供透明内容层和段落标题，不附带背景、头栏或字幕，也没有通用 `style` 参数 |
| `Panel` | `x / y / width / height` 必填；`tone="cyan"`、`opacity=1`，可传 `emphasis / children` |
| `Label` | `children` 必填，`size=24`，`muted` 切换次要文字色；当前 `tone` 参数未用于文字着色 |
| `AccentBar` | `tone="cyan"`、`width=46`，生成强调短线 |
| `Entered` | `delay=0`；`children` 是接收动画进度的函数，适合在列表子组件中使用 |
| `useEnter(delay=0, stiffness=120)` | 返回当前帧对应的弹簧入场进度 |
| `useFade(start=0, duration=18)` | 返回 0–1 的淡入进度 |
| `CANVAS` | 当前为 1920×1080 |

`SceneShell` 的段落标题不等于规范中的“章节标签＋章节主标题＋装饰线”组合。章节主标题按[视频画面规范第五节](视频画面规范V0.2.md#五章节主标题)组合；当前示例目录尚无对应独立示例，本索引也未将其列为独立公共组件。

### 3.3 颜色与动画函数

| 入口 | 可复用导出 |

| `four-accounts` | [A3FourAccounts](../../src/visual/templates/Cards14.tsx) | 固定四项 `items` 与可选 `stamp`；仍含“四笔账”栏目文字，适合相同语义场景 |
| `three-steps` | [A4ThreeSteps](../../src/visual/templates/Cards14.tsx) | `steps` 中的 `code / verb / full / output`；仍含“全章骨架”栏目文字 |

契约中的默认值通过 Schema 解析产生，直接把不完整对象传给 React 组件不会自动获得这些默认值。例如以下静态数据在入口解析一次，后续直接复用：

```tsx
import { TableTemplate } from "../../../visual/templates/TableTemplate";
import { TablePayloadSchema } from "../../../../contracts/visual-props.schema";

const payload = TablePayloadSchema.parse({
  title: "概念对照",
  headers: ["概念", "作用"],
  rows: [["目标", "说明要达成什么"], ["行动", "说明如何推进"]],
});

export const TableExample = () => <TableTemplate payload={payload} />;
```

当前 `TableTemplate` 未读取契约中的 `highlightRowIndices` 和 `footerBanner`，不能靠传入这两个字段实现高亮或底部横幅。需要逐行状态控制、不同列宽或单元格高亮时，先确认现有接口缺口，不把字段存在当作功能已实现。

模板以固定课程画幅编排内容，数组数量的 Schema 上限不代表任意长度的文字都能容纳。根据实际内容选择合适模板或在课时目录组合公共组件，不由题目长短改变 3 秒思考规则。

## 五、真题展示与时序边界

四种题卡统一从 [quiz.ts](../../src/visual/templates/quiz.ts) 导入。布局选择、口播聚焦、选项样式切换和审核要求见[题卡规范V0.1](题卡规范V0.1.md)，本节仅说明实际接口与限制。

| 入口 | 已有接口与功能 | 当前限制 |
| --- | --- | --- |
| [ExamQuizCard](../../src/visual/templates/ExamQuizCard.tsx) | `payload / cues / timing`；支持位置、尺寸、字号、列数、倒计时外观与 `rightSlot`；`renderOption / renderStatement` 可局部替换选项行或编号材料；可选 `variant="paper"` 合并题面，`height / analysisSlot / analysisFromFrame / analysisTop` 控制高度及下方解析 | `presentation` 提供公共逐项关注、判断与解析；`renderOption` 优先于公共选项表现，插槽仍由调用方负责 |
| [DualQuizBattleCard](../../src/visual/templates/DualQuizBattleCard.tsx) | `payload.leftQuiz / rightQuiz`、`timing.left / right`、`cues`、可选 `topComparisonTable`；左右等宽，分别思考与揭示 | 旧 cue 按左右整题处理；`presentation.left / right` 提供各题逐项关注、判断与解析，`cardStyles.left / right` 可控制焦点交接；`variant="paper"` 复用完整题面样式，`height` 控制等高题面，短解析独立置于各题下方 |
| [CompactQuizCard](../../src/visual/templates/CompactQuizCard.tsx) | `payload / cues / timing`、位置、尺寸、字号、列数、倒计时与 `active` | `presentation` 提供逐项关注、判断与解析；启用后非当前卡仍保持文字不透明，布局由调用方安排；`variant="paper"` 使用完整题面样式，短解析在卡内按内容自然展开 |
| [BriefQuizCard](../../src/visual/templates/BriefQuizCard.tsx) | `payload / timing`、`revealAt / enterAt / fillText`、位置、尺寸、字号和列数 | `presentation` 提供逐项关注、判断与解析；仍适合短题，不把长解释强塞进窄卡；`variant="paper"` 使用统一题头、双列短选项和答案章，独立示例提供四题组合 |
| [ResolvedCuePoint](../../contracts/visual-props.schema.ts) | `action / targetId? / localFrame / triggerMs / matchedBy` 等字段 | `localFrame` 相对当前场景；不能与整课全局帧混用 |

共同时间逻辑见 [quiz-timing.ts](../../src/visual/templates/quiz-timing.ts)。`timing.stemEndFrame` 传入当前题卡局部时间轴上的实际题干结束帧，立即开始三秒真实静音与倒计时，不等待选项朗读结束；`revealFrame` 是讲解中的答案时点。倒计时按 `fps` 换算三秒，默认判断事件不会早于思考结束。正式课时使用实际音频锚点，未提供思考起点时不会按场景比例自动补出停顿。

`ExamQuizCard` 的动作包括 `thinking-pause`、`eliminate-option`、`reveal-answer`、`show-tip`。逐项排错可使用选项键作为 `targetId`；`polarity="negative"` 表示选择错误表述，此时 `isCorrect` 表示表述本身是否正确，答案取 `isCorrect=false` 的项。

`DualQuizBattleCard` 优先用 `timing.left / right` 接入各题时点；旧 cue 的 `targetId="left" / "right"` 表示左右整题，不能直接套用单题的选项级 cue。

读题、思考停顿与答案揭示按[音频规范V0.2](音频规范V0.2.md)第五节执行。使用公共题卡仍需接入本课实际音频、停顿记录和讲解锚点；样式预览中的固定时间不用于正式课程。

### 5.1 公共颜色、讲解与过渡

从 `quiz.ts` 导入 `QuizPresentation` 类型与 `QUIZ_COLORS`。四种题卡传入 `presentation={}` 即启用公共颜色和帧过渡；省略时保留已有课时表现。实现见 [quiz-presentation.tsx](../../src/visual/templates/quiz-presentation.tsx)，不增加题目数据状态机或校验层。

| `presentation` 字段 | 含义与默认值 |
| --- | --- |
| `focus: [{targetId, from, to}]` | 选项字母对应的临时关注，均为局部帧；进入思考时清除读题关注，随后不能重新浮现 |
| `focusColor` | 仅覆盖临时关注色，默认 `colors.focus`；如 Exam 第 26 题用金色跟读，符合原则的判断仍用青色 |
| `judgements: [{targetId, from, label?}]` | 明确提供的逐项判断；默认符合原则为青色、表述有误为红色，已完成判断保留；不传就不擅自生成 |
| `explanations: [{text, from, to?}]` | 仅显示实际提供的解释；`to` 省略时保留，提供时淡出；没有文本则无面板、不预留解析空间 |
| `transitionSeconds` | 默认 `0.2` 秒，按 `fps` 确定帧数；底色与边框渐变，标签、答案章和解析淡入淡出 |
| `colors: {text?, focus?, error?, answer?, evidence?}` | 默认依次为 `#E6F1FA / #2EC4D6 / #E0605A / #4CC38A / #E0B050`，复用公共 token，可按需覆盖 |

判断、解析与答案不早于思考结束，答案动画从揭晓帧开始；反向题可同时显示红色错词和绿色“本题答案”章。固定标签槽保持题干、选项位置稳定。答案继续由原有 `timing.revealFrame` 或 cue 决定，不把解释出现自动当作公布答案。没有答案口播时，可显式使用 `stemEndFrame + QUIZ_THINK_SECONDS * fps`。

`ExamQuizCard` 的 `paper` 形式默认 `top=125 / height=400 / bodySize=20 / optionSize=17`，保留原位置、字号和列数覆盖。解析插槽从 `analysisFromFrame` 淡入且不早于思考结束，省略时等答案揭晓；内部逐项时序由插槽负责。未提供解析不生成空面板。省略 `variant` 保留原布局。倒计时可覆盖 `labelStyle / numberSize / showUnit / ringInset`，原有外观默认值不变。

`DualQuizBattleCard` 的 `paper` 形式默认 `top=155 / height=370 / bodySize=20 / optionSize=17 / columns=1`，左右等宽且从首帧完整显示。短解析继续使用各题 `presentation.explanations`，没有内容不生成面板；题干结束锚点、答案与解析仍分别按左右题处理。省略 `variant` 保留原课程布局。

`CompactQuizCard` 的 `paper` 形式默认 `left=120 / top=155 / width=820 / bodySize=20 / optionSize=17`，从首帧显示完整题面，倒计时采用 40px 无文字标签圆环。高度随实际内容增长；无解析不生成面板或额外占位。省略 `variant` 保留原课程行为。

`BriefQuizCard` 的 `paper` 形式默认 `left=120 / top=155 / width=820 / bodySize=20 / optionSize=17 / columns=2`，保留位置、尺寸、字号及入场时点覆盖。四题组合由示例负责，题卡继续接收每题独立的 `timing`；没有解析时不生成空面板。省略 `variant` 保留原课程行为。

完整接入与四个独立预览见 [src/examples/quiz/README.md](../../src/examples/quiz/README.md)。2026-11-06，四种题卡（含 Brief 四题版）的当前视觉效果已由用户确认通过。启动命令显式设置本例入口和素材目录，不加载全课程 Composition 汇总；例内题目与时序自足。无配音演示不能代替正式课时的音频、静音 PCM 与字幕同步验证。

## 八、课时接入与数据覆盖

### 8.1 独立课时组件

使用 [CompositionSpec](../../src/visual/composition-types.ts) 声明 `id / component / durationInFrames / fps / width / height`，可提供 `defaultProps / calculateMetadata`。

注册声明可参考独立示例：[quiz/compositions.ts](../../src/examples/quiz/compositions.ts) 与 [quiz/index.tsx](../../src/examples/quiz/index.tsx)。公共总入口是 [src/examples/index.tsx](../../src/examples/index.tsx)。演示课在 `src/lessons/test01/studio.tsx` 登记自己的 Composition，不进入公共入口。

`defaultProps` 提供 Composition 层的默认输入；真正能覆盖哪些内容，仍由课时组件自身的 Props 决定。

整课组装可复用 [resolve-full-lesson-groups.ts](../../src/pipeline/resolve-full-lesson-groups.ts)：

| 方法 | 输入与返回 | 边界 |
| --- | --- | --- |
| `resolveFullLessonGroups(lessonId, groups, specs)` | 每组提供 `id / composition / from / durationInFrames`；按 `composition` 匹配 `spec.id`，返回 `{group, spec, from, durationInFrames, props}`，`props` 为该组件的 `defaultProps` | 顺序与时间取组装记录，不依赖组件数组顺序；缺失时错误包含课时、分组和 composition id |
| `groupPreviewSpecs(data, create)` | 数据为 `null` 或 `undefined` 时返回 `[]`，否则调用 `create(data)` 返回一个 Composition 的列表 | 只用于尚无数据时省略单组预览；不免除整课对全部组的要求，也不处理静态导入文件缺失 |

课时整课组件负责用 `Sequence` 放置各组、关闭组内音轨与口播字幕，再在外层挂一条整轨音频和一层字幕。上述方法不生成音轨、字幕偏移或完整整课壳。

### 8.2 编译数据与课时专用组件

通用模板不能表达的课时设计，通过 `visualType: "chapter-local"`、`payload.key` 和 `payload.data` 指向本课组件表。组件表由该课入口传入母版，不集中登记到公共目录。

[ChapterComponent](../../src/visual/chapter-types.ts) 接收 `{ payload: unknown, cues?: ResolvedCuePoint[] }`。课时入口负责解释自己的数据，内部继续复用原子组件、kit 和公共方法，不新增另一套基本图形库。

默认公共 Studio 是 `src/examples/index.tsx`，命令是 `npm run studio`。它不导入课程，也不把某一节课当作母版默认数据。演示课入口是 `src/lessons/test01/studio.tsx`，命令是 `npm run studio -- --entry src/lessons/test01/studio.tsx`，只加载这一课的数据。公共母版不读取课程列表，专用组件由该课入口闭包传入。入口不读取 `workspaces/current-lesson.json`。`npm run check:public` 检查公共代码，`npm run check:course -- --course=test01` 加载演示课。

### 8.3 只改画面数据

[applyLessonPatches(lesson, patches)](../../src/pipeline/lesson-patches.ts) 按场景 ID 深合并对象，数组整体替换，返回应用补丁后的数据。例如：

```json
{
  "S01": {
    "payload": {
      "title": "本课需要显示的标题"
    }
  }
}
```

只有调用了 `applyLessonPatches` 的路线才会应用补丁；放置一个 `patches.json` 文件不会使所有 Composition 自动读取它。该方法适合画面文案和配置覆盖，不会同步重做口播、音频、字幕或对齐。

### 9.2 双版本交付：复用干净视频

公共入口：[scripts/compose-lesson.mjs](../../scripts/compose-lesson.mjs)，也导出 `composeLesson(options)` 供脚本调用。各课先渲染一次干净视频，再传入同版整轨音频和字幕生成有声字幕版；已有符合要求的干净版直接复用。公共入口已实现，用户已确认 GPU 小样通过。

| 参数 | 输入与默认行为 |
| --- | --- |
| `--lesson` | 必填本课标识，对应命令模板中的 `<lessonId>`；仅标记本次交付，不自动查找本课素材 |
| `--video` | 必填干净 MP4：1920×1080、恒定 30 fps、起点为 0、无音轨；调用方确认画面没有烧录口播字幕 |
| `--audio` | 必填同版、已处理音量的完整 PCM WAV，起点为 0 且覆盖所需范围；支持单声道或双声道 |
| `--captions` | 必填字幕 JSON 或 SRT；JSON 可为数组或含 `captions` 的对象，条目须有 `text/startMs/endMs`、按时间排序且不重叠。优先传 Studio 使用的同份 JSON，保留小数毫秒精度 |
| `--output` | 必填新有声 MP4 路径，后缀为 `.mp4` |
| `--start-frame` | 默认 `0`；干净样段在整课中的起始帧。它用于裁切整轨音频和字幕，不裁切输入视频 |
| `--wav-output`、`--srt-output`、`--info-output` | 可覆盖副产物路径；默认与有声 MP4 同名，后缀为 `.wav`、`.srt`、`.media-info.json` |
| `--video-bitrate` | 默认 `8M`，只设置有声版重新编码的码率 |
| `--browser-executable` | 默认 `/opt/google/chrome/chrome`，用于生成公共字幕透明图 |

相对路径从项目根目录解析，输入和各输出路径不能重合，已有输出拒绝覆盖。`node scripts/compose-lesson.mjs --help` 可查看命令说明。

脚本调用 `composeLesson(options)` 时，键名使用上表参数去掉 `--` 后的名称，例如 `{'start-frame': 240}`；返回 `{video, wav, srt, info}` 四个输出的绝对路径。

以下是整课命令模板，Agent 将占位符替换为本课真实标识、Composition 和路径后交给用户执行。干净版可沿用已确认的分段渲染方式；这里用 Remotion CLI 展示要求硬件编码的基本命令。所选 Composition 必须关闭口播字幕，`--muted` 只负责去掉音轨。

```bash
npx remotion render "<入口>" "<干净版 Composition>" \
  "deliverables/<lessonId>/silent-clean.mp4" \
  --codec=h264 --hardware-acceleration=required \
  --video-bitrate=8M --concurrency=4 \
  --image-format=jpeg --jpeg-quality=95 \
  --muted --overwrite=false --gl=angle \
  --browser-executable=/opt/google/chrome/chrome

node scripts/compose-lesson.mjs \
  --lesson="<lessonId>" \
  --video="deliverables/<lessonId>/silent-clean.mp4" \
  --audio="public/audio/<工作区标识>/narration.wav" \
  --captions="workspaces/<工作区标识>/captions.json" \
  --output="deliverables/<lessonId>/voiced-captioned.mp4" \
  --wav-output="deliverables/<lessonId>/full.wav" \
  --srt-output="deliverables/<lessonId>/subtitles.srt" \
  --info-output="deliverables/<lessonId>/media-info.json"
```

需要导出样段时，第一步如加 `--frames=240-389`，表示零起始、两端包含的 150 帧；第二步传该干净样段并加 `--start-frame=240`。**音频和字幕仍传整课版本**，入口按相同范围裁切并归零，输出 WAV / SRT 与样段一致。样段放在 `out/<lessonId>/`，不得作为整课交付。

- 字幕沿用 `CaptionsOverlay`，每个不同文本只生成一张透明图，按原字幕时间叠加；空白窗口来自传入数据，不在导出时重新安排思考停顿。
- 视频使用 CUDA 解码、`overlay_cuda` 叠加和 `h264_nvenc` 编码；PNG 解码与格式转换、音频处理使用 CPU。GPU 失败报错并保留临时文件，不自动改用 CPU 视频渲染。
- 输出 WAV 为 24 kHz 双声道 PCM16，MP4 音轨为 48 kHz 双声道 AAC；单声道等幅复制到左右声道，不再次归一化、淡入淡出或压限。
- 入口核对输出轨道、尺寸、帧率、帧数、音频格式、起点和时长。JSON 记录 `sources`、`range`、`outputs` 及 `video` / `wav` 媒体参数；用户视听验收结论继续写入本课记录。
- 干净版保留为独立交付和合成输入。有声版仍需重新编码，节省的是教学组件、布局和动画的再次计算；不承诺固定提速幅度，也不要求每课重复性能校准。

### 9.3 原有共享单版导出

入口：[scripts/render-lesson.mjs](../../scripts/render-lesson.mjs) 的 `renderLesson`。主要参数为 `--lesson`、`--composition`、`--audio`、`--srt`、`--output`，可选 `--frames`、`--silent-clean`、`--entry`。`--entry` 是本次打包使用的入口文件。

- 使用本课干净版 Composition 并加 `--silent-clean` 可导出无声版，无需传 `--audio`；组件须支持关闭口播字幕或本身就是无字幕入口。
- `--frames` 两端包含；有声版音频和配套 SRT 按同一范围裁切，SRT 时间归零。
- 当前最多拆成四段并行，使用 Chrome `/opt/google/chrome/chrome`，硬件编码设置为 `if-possible`；实际编码器以日志为准。
- 有声版在画面完成后合入连续音轨；传入的 SRT 只用于独立字幕文件，画面字幕仍由 Composition 绘制。
- 一次输出 MP4、配套 SRT 和媒体参数 JSON；独立 WAV 归档另行处理，成片和媒体信息文件拒绝覆盖。

函数调用另支持 `inputProps`；`silentClean: true` 会设置 `includeAudio: false`、`includeCaptions: false` 与 `silentClean: true`，组件须实际响应这些参数。干净版编排可传 `sidecars: false`，只输出 MP4，无需 SRT 输入；这些是函数选项，不是新增 CLI 参数。

上述 `renderLesson` 不会自动调用 `composeLesson`。双版本交付时先取得干净版，再显式调用 9.2 的公共合成入口；分别调用该单版导出入口生成有声、无声版仍会分别计算画面。

### 9.4 通用编译与原有交付路线

| 入口 | 当前用途与限制 |
| --- | --- |
| [compile.ts](../../src/cli/compile.ts) / `npm run compile` | 接收 `--input`、`--lesson`、`--audio-mode=cuda`；按现有口播与分镜输入格式完成解析、音频和绑定。没有通用 `--group` 或 `--only` 参数，不能直接把任意纯口播文件当作完整流水线输入 |
| [render.ts](../../src/cli/render.ts) / `npm run render` | 接收 `--lesson`。渲染干净版时还要 `--entry` 和 `--composition`。可选 `--max-frames`、`--frames=起始-结束`、`--clean=<已有干净 MP4>`。读取该课 `compiled-lesson.json`，按调用方给出的入口渲染一次 |
| [deliverCompiledLesson](../../src/pipeline/4-render/dual-delivery.ts) | `(lesson: CompiledLesson, projectRoot, options?)`；选项为 `frames`、`maxFrames`、`cleanVideo`、`entry`、`composition`。无干净版时使用调用方提供的入口和 Composition，只渲染一次干净画面，再调用 `composeLesson()`。帧范围同时用于视频、WAV 和 SRT，样段字幕归零 |
| [renderLessonDeliverables](../../src/pipeline/4-render/nvenc-renderer.ts) | 上一方法的兼容调用入口，供 `npm run render` 使用，不另实现一套渲染流程 |

`npm run render` 已接入 9.2。它不把有声版和干净版各算一遍教学画面。直接执行 `render-lesson.mjs` 仍然只导出调用方指定的那一版，不会自动合成。按组配音与对齐已支持 `--workspace=<分组目录>`，见第七节；`npm run compile` 与 `npm run render` 尚无统一的 `--group`／`--only` 选择接口，按本节列出的参数使用。

当前限制：

- 编排接收 `CompiledLesson`，以及调用方提供的入口和干净版 Composition。字幕来自 `workspaces/<lessonId>/compiled-lesson.json`，音频来自同目录 `<lessonId>-full.wav`。独立课时组件暂按 9.2 使用本课 Composition 和媒体输入。
- 输出固定在 `deliverables/<lessonId>/`，样段与整课使用同一套文件名，已有产物拒绝覆盖。先出样段会占用整课路径；样段暂按 9.2 指定 `out/<lessonId>/` 内的新路径。可指定输出位置或按帧范围区分文件名的接口尚未实现。
- `--clean` 接收同版干净视频：帧数等于请求范围时按已裁好的样段复用，更长时尝试流复制裁出该范围，保留原文件。非零起点须匹配关键帧，否则报错并要求按该范围重新渲染干净版。

### 9.5 讲义公共处理与完整示例

公共入口：[scripts/handout.py](../../scripts/handout.py) 的 `build_handout()`，也可直接作为 CLI 使用。完整示例在 [src/examples/handout/](../../src/examples/handout/README.md)，包含唯一页面数据、三张本地配图、直接调用代码及[此前审核的三页样式参考 PDF](../../src/examples/handout/reference/handout-example.pdf)。当前示例直接使用图片，不显示旧视频时间；页面组织、配图处理和新课接入均在示例 README 内说明，运行无需读取原课程文件，参考 PDF 保留原版。

新课维护一份页面输入（如 `handout.json`），调用公共入口生成 `selection.json`，不手工维护两份相同内容。页面拆分、选帧、裁切和已有参数的覆盖由 Agent 按教学需要决定；具体流程见[讲义制作方案](教学讲义制作方案V0.1.md)。

```bash
# 使用已安装 Pillow、ReportLab 的 Python；字体与本机已验证命令见示例 README。
python3 src/examples/handout/run.py

# 新课：路径按本课实际输入与新版本输出目录填写。
python3 scripts/handout.py --data /path/to/handout.json --assets /path/to/assets --output /path/to/handout-v1
```

| 输入 / 行为 | 实际接口与边界 |
| --- | --- |
| 必填参数 | `pages`、`lesson`、`asset_dir`、`output_dir`；`lesson.title` 必填；每页提供 `id/title/kind/image` |
| 课时内容 | `crop=[宽,高,左,上]`、标题、解释、笔记提示、`chapter` 书签及选帧依据由调用方维护；裁切省略或为 `null` 时保留全图 |
| 时间 | 可直接提供页面 `time`；否则由实际 `frame / lesson.fps` 生成；两者都无则不显示时间。不读取课时组装记录或视频，分组偏移由调用方处理 |
| 公共默认 | 横向 A4、28pt 边距、20pt 标题、10pt 正文、两行笔记区；JPEG 质量 95、无色度抽样降质，默认不缩小输入像素 |
| 可覆盖项 | `style`（边距、字号、行距、笔记行数、颜色）、`fonts`（中文和符号 TTF）、`image_options`（JPEG 与预览参数）、`pdf_name`；完整字段见示例 README 和源码中的默认配置 |
| 输出 | PDF、自动生成的 `selection.json`、`images-jpeg/` 与独立轻量 `previews/`；始终保留输入原图，默认拒绝覆盖已有输出 |
| 目录关系 | 输入素材目录与输出目录不能相同或互相包含；修订使用新的输出版本目录，保留已有成果 |
| 当前限制 | 不自动选帧、不判断题目或解释的教学正确性、不做 GPU 截帧；缺图时仍由用户执行完整 GPU 命令，先保留原帧再裁切 |

公共 CLI 与示例已实际运行，三页版面及独立运行检查通过，**代表性 PDF 已通过用户审核**。沿用这一结论，正式课时核对本课内容、版本与本次受影响的页面，再交由用户阅读验收；旧课脚本不强制迁移。
