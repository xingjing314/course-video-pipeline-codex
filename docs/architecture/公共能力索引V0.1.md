## 一、使用方式与入口速查

先按教学需要查找已有能力，再通过参数覆盖、组合或现有插槽完成课时设计。只有确有功能缺口时才新增实现；课时内容和专用设计留在 `src/lessons/<章节>/<课时>/`。

公共目录中的组件不一定都支持省略参数、样式覆盖或局部替换，以实际 Props 为准。当前组合组件可从 `src/visual/kit` 导入；其他能力按下表对应模块导入。

| 要做什么 | 优先查看 | 当前使用边界 |
| --- | --- | --- |

## 二、原子图形

### 2.1 入口与配置

- 实现目录：[primitives/codex-version](../../src/visual/primitives/codex-version)。
- 注册表：[PRIMITIVE_COMPONENTS / PRIMITIVE_IDS](../../src/visual/primitives/registry.ts)，建立图元 ID 与组件的对应关系。
- 数据契约：[AtomicShapeItemSchema / PrimitiveId](../../contracts/primitives.schema.ts)。
- 配置样例：[data](../../src/visual/primitives/codex-version/data)；[samples.generated.ts](../../src/visual/primitives/codex-version/data/samples.generated.ts) 导出 `PRIMITIVE_SAMPLE_CONFIGS`，该生成文件不手改。

原子组件接收 `config` 和 `localFrame`，输出 SVG `<g>`，调用方提供外层 `<svg>`。直接导入具体组件可保留具体配置类型；按数据选择图元时，可使用 `AtomicCombo`。

**当前并没有统一的“只传少量字段就自动补齐全部配置”的图元接口。** 例如 `Rect01` 要求完整的 `Rect01Config`。可以复用现有样例或课时已确认配置，再覆盖嵌套字段；样例中的位置、颜色和动画时间属于演示配置，不等于本课的设计与时序。

### 2.3 配置覆盖示例

以下示例假定组件位于 `src/lessons/ch08/L02/Example.tsx`；其他位置应调整相对导入路径。它只演示复用方式，不要求建立这个示例文件。

```tsx
import { useCurrentFrame } from "remotion";
import { Rect01 } from "../../../visual/primitives/codex-version/_01Rect";
import type { Rect01Config } from "../../../visual/primitives/codex-version/_01RectConfig";
import sample from "../../../visual/primitives/codex-version/data/_01-rect.json";

const config: Rect01Config = {
  ...sample,
  rect: { ...sample.rect, x: 120, y: 300, width: 480, height: 240 },
  animation: {
    ...sample.animation,
    outlineStartFrame: 0,
    fillStartFrame: 12,
  },
};

export const ShapeExample = ({ startFrame }: { startFrame: number }) => {
  const frame = useCurrentFrame();
  return (
    <svg width={1920} height={1080} viewBox="0 0 1920 1080">
      <Rect01 config={config} localFrame={frame - startFrame} />
    </svg>
  );
};
```

`startFrame` 由本课音频锚点提供，并与当前组件处于同一时间坐标。`fillStartFrame` 等是图元自身入场动画的相对时间，不替代口播定位。

## 三、组合组件、布局与动效

### 3.1 kit：可以直接组合的组件

统一从 [src/visual/kit/index.ts](../../src/visual/kit/index.ts) 导入。

| 能力 | 必填输入 | 可覆盖项与当前默认行为 |
| --- | --- | --- |
| `CardGrid` | `items`、`left`、`top` | `columns=2`、`cardWidth=540`、`cardHeight=210`、`gap=140`、`enter=1`、`stagger=false`；可传 `states` |
| `Flow` | `steps`、`left`、`top` | `nodeWidth=220`、`nodeHeight=96`、`gap=48`；`activeIndex=-1`、`doneThrough=-1`；`activeIndices` 优先于单个 `activeIndex` |
| `Scale` | `marks`、`left`、`top`、`width` | `fillTo` 默认取激活刻度位置，否则为 0；`breakAt`、`breakLabel` 可显示断层 |
| `useStepper(cuts)` | 本地帧切点数组 | 返回 `passed`、`current`、`states`、`stateOf(index)`；未开始时 `current=-1` |
| `stepStates(cuts, frame)` | 切点数组、当前帧 | `useStepper` 对应的纯计算函数；状态为 `past / current / future`，最后一步保持 `current` |
| `cueCuts(cues, action?)` | 已解析的 cue 数组 | 默认筛选 `highlight-item`，返回升序 `localFrame` |
| `useStep(cuts)` | 本地帧切点数组 | 只返回已到达的切点数量 |
| `Stagger` | `children` | `index=0`、`step=6`，按 `index × step` 帧错峰入场 |

数据类型：`CardItem` 为 `{ name, line?, tone?, tag? }`；`FlowStep` 为 `{ label, code?, sub?, tone? }`；`ScaleMark` 为 `{ at, label, active?, tone? }`，其中 `at` 使用 0–1 的相对位置。

`CardGrid` 的 `enter` 与 `stagger` 选择一种入场方式；`states` 中的 `future` 只是压暗，不会隐藏内容，不能把它当作防止答案提前出现的机制。

同样以 `src/lessons/ch08/L02/Example.tsx` 为例：

```tsx
import { CardGrid, cueCuts, useStepper } from "../../../visual/kit";
import type { ResolvedCuePoint } from "../../../../contracts/visual-props.schema";

export const CardsExample = ({ cues }: { cues: ResolvedCuePoint[] }) => {
  const steps = useStepper(cueCuts(cues));
  return (
    <CardGrid
      items={[{ name: "目标" }, { name: "行动" }, { name: "结果" }]}
      left={96}
      top={300}
      columns={3}
      cardWidth={500}
      gap={40}
      states={steps.states}
    />
  );
};
```

本例省略的卡片高度沿用默认值。cue 的顺序应对应卡片顺序；`cueCuts` 按动作筛选，不按 `targetId` 自动匹配卡片。

### 3.2 公共面板与局部标题

入口：[templates/shared.tsx](../../src/visual/templates/shared.tsx)。

| 导出 | 用法与边界 |
| --- | --- |

| `Panel` | `x / y / width / height` 必填；`tone="cyan"`、`opacity=1`，可传 `emphasis / children` |

这些组件一般接收 `payload`；数据结构在 [visual-props.schema.ts](../../contracts/visual-props.schema.ts)，路由在 [SceneRouter.tsx](../../src/visual/templates/SceneRouter.tsx)。既可以通过编译场景调用，也可以在课时组件中直接组合。

| `visualType` | 组件 / 文件 | 主要输入与当前能力 |

| `multi-cards` | [MultiCards](../../src/visual/templates/MultiCards.tsx) | `title / cards`，每卡可配正文、色调、角标和提示；支持上下提示横幅 |
| `formula-card` | [FormulaCard](../../src/visual/templates/FormulaCard.tsx) | `title / formula / variables / note?`；公式与变量说明 |
| `bar-chart` | [BarChartCard](../../src/visual/templates/BarChartCard.tsx) | `title / series`，可选 `unit / maxValue / caption`；未传上限时取最大数据值的 1.15 倍 |
| `chapter-map` | [ChapterMapCard](../../src/visual/templates/ChapterMapCard.tsx) | `title / chapters / activeIndex?`；`activeIndex` 对应条目的 `index`，不是数组下标 |
| `roadmap-summary` | [RoadmapSummaryCard](../../src/visual/templates/RoadmapSummaryCard.tsx) | `title / phases`，每阶段含 `period / title / items / tone?` |

| `chapter-timeline` | [A2Timeline](../../src/visual/templates/Cards14.tsx) | `before / after` 两侧内容，可选问题、结论和轴标签；固定为前后对照结构 |
| `four-accounts` | [A3FourAccounts](../../src/visual/templates/Cards14.tsx) | 固定四项 `items` 与可选 `stamp`；仍含“四笔账”栏目文字，适合相同语义场景 |
| `three-steps` | [A4ThreeSteps](../../src/visual/templates/Cards14.tsx) | `steps` 中的 `code / verb / full / output`；仍含“全章骨架”栏目文字 |

契约中的默认值通过 Schema 解析产生，直接把不完整对象传给 React 组件不会自动获得这些默认值。例如以下静态数据在入口解析一次，后续直接复用：

```tsx
import { TableTemplate } from "../../../visual/templates/TableTemplate";
import { TablePayloadSchema } from "../../../../contracts/visual-props.schema";

const payload = TablePayloadSchema.parse({
  title: "概念对照",
  headers: ["概念", "作用"],
  rows: [["目标", "说明要达成什么"], ["行动", "说明如何推进"]],
});

export const TableExample = () => <TableTemplate payload={payload} />;
```

当前 `TableTemplate` 未读取契约中的 `highlightRowIndices` 和 `footerBanner`，不能靠传入这两个字段实现高亮或底部横幅。需要逐行状态控制、不同列宽或单元格高亮时，先确认现有接口缺口，不把字段存在当作功能已实现。

模板以固定课程画幅编排内容，数组数量的 Schema 上限不代表任意长度的文字都能容纳。根据实际内容选择合适模板或在课时目录组合公共组件，不由题目长短改变 3 秒思考规则。

## 五、真题展示与时序边界

四种题卡统一从 [quiz.ts](../../src/visual/templates/quiz.ts) 导入。布局选择、口播聚焦、选项样式切换和审核要求见[题卡规范V0.1](题卡规范V0.1.md)，本节仅说明实际接口与限制。

| 入口 | 已有接口与功能 | 当前限制 |
| --- | --- | --- |
| [ExamQuizCard](../../src/visual/templates/ExamQuizCard.tsx) | `payload / cues / timing`；支持位置、尺寸、字号、列数、倒计时外观与 `rightSlot`；`renderOption / renderStatement` 可局部替换选项行或编号材料 | 默认选项入场是固定错峰；逐项跟读可通过已有插槽接入，插槽内的判断和答案样式由调用方负责 |
| [DualQuizBattleCard](../../src/visual/templates/DualQuizBattleCard.tsx) | `payload.leftQuiz / rightQuiz`、`timing.left / right`、`cues`、可选 `topComparisonTable`；左右等宽，分别思考与揭示 | 当前 cue 主要按左右整题处理，尚无逐选项阅读焦点接口 |
| [CompactQuizCard](../../src/visual/templates/CompactQuizCard.tsx) | `payload / cues / timing`、位置、尺寸、字号、列数、倒计时与 `active` | `active` 控制整卡强调，尚无逐选项阅读焦点接口；并排时由课时布局保证两卡一样大 |
| [BriefQuizCard](../../src/visual/templates/BriefQuizCard.tsx) | `payload / timing`、`revealAt / enterAt / fillText`、位置、尺寸、字号和列数 | 适合短题或补充题，尚无逐项排错与阅读焦点接口 |
| [ResolvedCuePoint](../../contracts/visual-props.schema.ts) | `action / targetId? / localFrame / triggerMs / matchedBy` 等字段 | `localFrame` 相对当前场景；不能与整课全局帧混用 |

共同时间逻辑见 [quiz-timing.ts](../../src/visual/templates/quiz-timing.ts)。`timing.stemEndFrame` 沿用现有字段名，传入当前题卡局部时间轴上的实际思考起始帧；`revealFrame` 是讲解中的答案时点。倒计时按 `fps` 换算三秒，默认判断事件不会早于思考结束。正式课时使用实际音频锚点，未提供思考起点时不会按场景比例自动补出停顿。

`ExamQuizCard` 的动作包括 `thinking-pause`、`eliminate-option`、`reveal-answer`、`show-tip`。逐项排错可使用选项键作为 `targetId`；`polarity="negative"` 表示选择错误表述，此时 `isCorrect` 表示表述本身是否正确，答案取 `isCorrect=false` 的项。

`DualQuizBattleCard` 优先用 `timing.left / right` 接入各题时点；旧 cue 的 `targetId="left" / "right"` 表示左右整题，不能直接套用单题的选项级 cue。

读题、思考停顿与答案揭示按[音频规范V0.2](音频规范V0.2.md)第五节执行。使用公共题卡仍需接入本课实际音频、停顿记录和讲解锚点；样式预览中的固定时间不用于正式课程。

| [CaptionsOverlay](../../src/visual/shell/CaptionsOverlay.tsx) | `captions: CaptionSegment[]`，按当前帧显示字幕 | 不接收 SRT 路径；字号、位置、底框等固定在组件内，没有通用样式覆盖参数 |
| [MasterCanvas](../../src/visual/shell/MasterCanvas.tsx) | `lesson / includeAudio / includeCaptions` | 组装背景、音轨、场景、头栏和字幕；适用于 `CompiledLesson` 路线，不是所有课时组件的必经入口 |

按[视频画面规范V0.2](视频画面规范V0.2.md)第二节，在课时配置入口使用：

```tsx
import { TechNetwork } from "../../../visual/backgrounds/tech-network/TechNetwork";
import { techNetworkSchema } from "../../../visual/backgrounds/tech-network/schema";

const background = techNetworkSchema.parse({
  type: "tech-network",
  ganttEnabled: false,
  linkOpacity: 0.035,
  nodeOpacity: 0.06,
  highlightCoreOpacity: 0.1,
  highlightGlowOpacity: 0.06,
});

export const BackgroundExample = () => <TechNetwork {...background} />;
```

当前 `MasterCanvas` 内部仍只解析 `{ type: "tech-network" }`，且没有背景配置 Props；其背景默认行为尚未与上述规范统一。不要额外叠一层背景来覆盖它。该问题属于已记录的公共实现更新项。

字幕使用所在画面时间轴对应的 `captions[]`；字幕为空依赖字幕数据本身不存在覆盖该时间的条目，不能只凭音频无 token 推断已经清空。无声版关闭的是音轨和口播字幕，保留教学文字与导航。

## 八、课时接入与数据覆盖

### 8.1 独立课时组件

使用 [CompositionSpec](../../src/lessons/composition-types.ts) 声明 `id / component / durationInFrames / fps / width / height`，可提供 `defaultProps / calculateMetadata`。

现有接入示例：[ch06/L02/index.ts](../../src/lessons/ch06/L02/index.ts) → [ch06/index.ts](../../src/lessons/ch06/index.ts) → [visual/compositions.tsx](../../src/visual/compositions.tsx) → [Root.tsx](../../src/visual/Root.tsx)。新内容段在所属课时入口中登记，不在公共汇总里逐段堆积。

`defaultProps` 提供 Composition 层的默认输入；真正能覆盖哪些内容，仍由课时组件自身的 Props 决定。

### 8.2 编译数据与课时专用组件

编译数据路线使用 [LESSONS / CHAPTERS](../../src/lessons/registry.ts)。通用模板不能表达的课时设计，通过 `visualType: "chapter-local"`、`payload.key` 和 `payload.data` 指向本课组件表。

[ChapterComponent](../../src/lessons/types.ts) 接收 `{ payload: unknown, cues?: ResolvedCuePoint[] }`。课时入口负责解释自己的数据，内部继续复用原子组件、kit 和公共方法，不新增另一套基本图形库。

### 8.3 只改画面数据

[applyLessonPatches(lesson, patches)](../../src/lessons/patches.ts) 按场景 ID 深合并对象，数组整体替换，返回应用补丁后的数据。例如：

```json
{
  "S01": {
    "payload": {
      "title": "本课需要显示的标题"
    }
  }
}
```

只有调用了 `applyLessonPatches` 的路线才会应用补丁；放置一个 `patches.json` 文件不会使所有 Composition 自动读取它。该方法适合画面文案和配置覆盖，不会同步重做口播、音频、字幕或对齐。

## 九、现有预览与导出命令

以下命令在项目根目录执行。需要 GPU 的生成、对齐、渲染、字幕截帧与视频合成命令由 Agent 准备、用户执行。

### 9.1 Studio

```bash
npm run studio
npm run studio -- --port=3027
```

入口是 [scripts/studio.mjs](../../scripts/studio.mjs)，默认端口 3025，`npm run dev` 调用同一脚本。实际地址以启动日志为准。

### 9.2 双版本交付：复用干净视频

公共入口：[scripts/compose-lesson.mjs](../../scripts/compose-lesson.mjs)，也导出 `composeLesson(options)` 供脚本调用。各课先渲染一次干净视频，再传入同版整轨音频和字幕生成有声字幕版；已有符合要求的干净版直接复用。公共入口已实现，用户已确认 GPU 小样通过。

| 参数 | 输入与默认行为 |
| --- | --- |
| `--lesson` | 必填课时标识，例如 `ch06-L02`；仅标记本次交付，不自动查找本课素材 |
| `--video` | 必填干净 MP4：1920×1080、恒定 30 fps、起点为 0、无音轨；调用方确认画面没有烧录口播字幕 |
| `--audio` | 必填同版、已处理音量的完整 PCM WAV，起点为 0 且覆盖所需范围；支持单声道或双声道 |
| `--captions` | 必填字幕 JSON 或 SRT；JSON 可为数组或含 `captions` 的对象，条目须有 `text/startMs/endMs`、按时间排序且不重叠。优先传 Studio 使用的同份 JSON，保留小数毫秒精度 |
| `--output` | 必填新有声 MP4 路径，后缀为 `.mp4` |
| `--start-frame` | 默认 `0`；干净样段在整课中的起始帧。它用于裁切整轨音频和字幕，不裁切输入视频 |
| `--wav-output`、`--srt-output`、`--info-output` | 可覆盖副产物路径；默认与有声 MP4 同名，后缀为 `.wav`、`.srt`、`.media-info.json` |
| `--video-bitrate` | 默认 `8M`，只设置有声版重新编码的码率 |
| `--browser-executable` | 默认 `/opt/google/chrome/chrome`，用于生成公共字幕透明图 |

相对路径从项目根目录解析，输入和各输出路径不能重合，已有输出拒绝覆盖。`node scripts/compose-lesson.mjs --help` 可查看命令说明。

脚本调用 `composeLesson(options)` 时，键名使用上表参数去掉 `--` 后的名称，例如 `{'start-frame': 240}`；返回 `{video, wav, srt, info}` 四个输出的绝对路径。

以下是整课命令模板，Agent 将占位符替换为本课真实标识、Composition 和路径后交给用户执行。干净版可沿用已确认的分段渲染方式；这里用 Remotion CLI 展示要求硬件编码的基本命令。所选 Composition 必须关闭口播字幕，`--muted` 只负责去掉音轨。

```bash
npx remotion render src/visual/index.ts "<本课干净版Composition>" \
  "deliverables/<lessonId>/silent-clean.mp4" \
  --codec=h264 --hardware-acceleration=required \
  --video-bitrate=8M --concurrency=4 \
  --image-format=jpeg --jpeg-quality=95 \
  --muted --overwrite=false --gl=angle \
  --browser-executable=/opt/google/chrome/chrome

node scripts/compose-lesson.mjs \
  --lesson="<lessonId>" \
  --video="deliverables/<lessonId>/silent-clean.mp4" \
  --audio="public/audio/<工作区标识>/narration.wav" \
  --captions="workspaces/<工作区标识>/captions.json" \
  --output="deliverables/<lessonId>/voiced-captioned.mp4" \
  --wav-output="deliverables/<lessonId>/full.wav" \
  --srt-output="deliverables/<lessonId>/subtitles.srt" \
  --info-output="deliverables/<lessonId>/media-info.json"
```

需要导出样段时，第一步如加 `--frames=240-389`，表示零起始、两端包含的 150 帧；第二步传该干净样段并加 `--start-frame=240`。**音频和字幕仍传整课版本**，入口按相同范围裁切并归零，输出 WAV / SRT 与样段一致。样段放在 `out/<lessonId>/`，不得作为整课交付。

- 字幕沿用 `CaptionsOverlay`，每个不同文本只生成一张透明图，按原字幕时间叠加；空白窗口来自传入数据，不在导出时重新安排思考停顿。
- 视频使用 CUDA 解码、`overlay_cuda` 叠加和 `h264_nvenc` 编码；PNG 解码与格式转换、音频处理使用 CPU。GPU 失败报错并保留临时文件，不自动改用 CPU 视频渲染。
- 输出 WAV 为 24 kHz 双声道 PCM16，MP4 音轨为 48 kHz 双声道 AAC；单声道等幅复制到左右声道，不再次归一化、淡入淡出或压限。
- 入口核对输出轨道、尺寸、帧率、帧数、音频格式、起点和时长。JSON 记录 `sources`、`range`、`outputs` 及 `video` / `wav` 媒体参数；用户视听验收结论继续写入本课记录。
- 干净版保留为独立交付和合成输入。有声版仍需重新编码，节省的是教学组件、布局和动画的再次计算；不承诺固定提速幅度，也不要求每课重复性能校准。

### 9.3 原有共享单版导出

入口：[scripts/render-lesson.mjs](../../scripts/render-lesson.mjs) 的 `renderLesson`。主要参数为 `--lesson`、`--composition`、`--audio`、`--srt`、`--output`，可选 `--frames`、`--silent-clean`。

- 使用本课干净版 Composition 并加 `--silent-clean` 可导出无声版，无需传 `--audio`；组件须支持关闭口播字幕或本身就是无字幕入口。
- `--frames` 两端包含；有声版音频和配套 SRT 按同一范围裁切，SRT 时间归零。
- 当前最多拆成四段并行，使用 Chrome `/opt/google/chrome/chrome`，硬件编码设置为 `if-possible`；实际编码器以日志为准。
- 有声版在画面完成后合入连续音轨；传入的 SRT 只用于独立字幕文件，画面字幕仍由 Composition 绘制。
- 一次输出 MP4、配套 SRT 和媒体参数 JSON；独立 WAV 归档另行处理，成片和媒体信息文件拒绝覆盖。

该入口及 [render-ch06-l01.mjs](../../scripts/render-ch06-l01.mjs)、[render-ch06-l02.mjs](../../scripts/render-ch06-l02.mjs) 课时包装脚本均未自动调用 `composeLesson`。双版本交付时先取得干净版，再显式调用 9.2 的公共合成入口；分别调用原脚本导出有声、无声版仍会分别计算画面。

### 9.4 通用编译与原有交付路线

| 入口 | 当前用途与限制 |
| --- | --- |
| [compile.ts](../../src/cli/compile.ts) / `npm run compile` | 接收 `--input`、`--lesson`、`--audio-mode=cuda`；按现有口播与分镜输入格式完成解析、音频和绑定。没有通用 `--group` 或 `--only` 参数，不能直接把任意纯口播文件当作完整流水线输入 |
| [render.ts](../../src/cli/render.ts) / `npm run render` | 接收 `--lesson`、可选 `--max-frames`，读取对应 workspace 的编译结果 |
| [renderLessonDeliverables](../../src/pipeline/4-render/nvenc-renderer.ts) | 渲染 `CourseVideo` 的有声字幕版和无声版，复制 WAV / SRT 并生成交付清单；当前两个版本各执行一次完整渲染 |

`npm run render` 保留上述原有行为，尚未自动接入 9.2 的公共合成流程。通用分组 GPU 参数仍未统一，不能把其他项目的命令参数当成本项目已支持的接口。
