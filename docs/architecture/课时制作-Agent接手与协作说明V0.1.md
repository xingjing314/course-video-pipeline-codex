# 课时制作：Agent 接手与协作说明 V0.1

日期：2026-10-27。适用范围：独立接手一个课时，沿用已确认的展示规则与审核方式。

本说明落实[有限架构调整方案](多课时并行制作-有限架构调整方案V0.1.md)阶段 D 的文档部分。当前尚未开展其他 agent 接手新课样段或两个工作目录分别编辑的试点；试点课时、范围及负责者由用户另行确定。

## 一、接手时先填写这张任务卡

由用户或负责整合的 agent 提供，接手者补齐实际路径。示例不代表已经分配任务。

| 字段 | 填写内容 |
| --- | --- |
| 负责课时 | 完整标识，例如 `ch06-L02`；既有带后缀课号继续沿用 |
| 输入稿 | 本工作目录内的实际路径、版本；L02 已有稿见[输入稿](../lessons/ch06/L02/input/第6章-L02完整口播稿V0.3.md) |
| 工作目录 / 分支 / 基线提交 | 分别填写绝对路径、分支名称、包含已确认架构调整的 commit |
| 预览端口 / Composition | 分配的空闲端口、该课实际注册的入口；未创建的入口注明“待制作” |
| 本轮范围与停止点 | 例如“只做一段有声小样，交用户审核后停止”；写清已通过的段落 |
| 本地素材 | 配音、教材图、题库等实际来源及本课存放位置；缺项明确列出 |
| 负责整合者 | 协调公共文件修改、代码合并和媒体归档的人或 agent |

接手后的首次反馈应简短说明：输入稿是否找到、哪些内容已通过、这轮准备做什么、是否存在阻碍。已有明确授权和结论直接沿用，不重复让用户确认同一件事。

## 二、准备独立工作目录与素材

1. 同机优先使用独立分支和独立 worktree；仅在同一目录切换分支不能隔离同时写入。用户选择复制项目时，也应分开工作目录、输出和端口。
2. **分发前先保存已确认基线。** 2026-10-27 本轮查看时，目录迁移及 A—C 改动仍有暂存、未暂存和未跟踪文件。新 worktree 从提交创建，不会自动带入这些内容。由整合者在用户授权提交后，将确认的变更纳入基线，再创建制作目录；本说明不执行提交或分发。
3. 在自己的目录检查 Git 状态，保留已有修改。按需安装锁文件指定的依赖（当前 Node.js 24 / npm，`npm ci`）；不清理主目录的依赖和素材。
4. Git 不包含 `public/audio/`、WAV、交付视频及讲义图片。按课复制或从备份恢复素材，保持组件引用的相对路径；新配音写入本课目录。不要把另一任务的可写音频目录链接成自己的输出。
5. 参考 L01 时，其整课播放音轨为 `public/audio/ch06-L01-full/narration.wav`；分段预览还可能需要对应分段音频。第七章本地音频此前已清理，历史代码存在不代表音频齐备。
6. 本机 Chrome 固定为 `/opt/google/chrome/chrome`；TTS 和对齐器分别使用 `/projects/gaoxiang/qwen3-tts/`、`/projects/gaoxiang/qwen3-forced-aligner/` 下的环境。FFmpeg / ffprobe、讲义依赖等见 [README 环境说明](../../README.md#五外部环境与素材依赖)。接手机器按实际需要确认路径，不为尚未遇到的问题建设部署系统。
7. RTX 5060 Ti 16GB 优先用于适合加速的工作。多任务的重型 TTS、对齐、整课导出先人工错峰。遇到权限或驱动障碍，说明原因、最小操作和需要返回的结果，不静默改用 CPU 长时间运行。

预览在自己的项目根目录启动，下面的 3027 仅为示例，使用任务卡分配的空闲端口：

```bash
npm run studio -- --port=3027
```

默认端口仍为 3025；被占用时换用空闲端口，不停止别人的服务。进入自己课时的 Composition；新课尚未注册时，先按下一节接入，不能只改 URL 就得到新课。

## 三、哪些文件属于本课

以下为新课约定，按实际课号替换；既有 L01 内容和分段路径保持原状。

| 用途 | 本课位置 |
| --- | --- |
| 输入稿与制作记录 | `docs/lessons/<章节>/<课时>/`，输入稿放在 `input/` |
| 内容组件、入口声明 | `src/lessons/<章节>/<课时>/`，入口声明放在 `index.ts` |
| 必要的课时专用脚本 | `scripts/<lessonId>/`，按需建立 |
| 时间线、字幕与制作数据 | `workspaces/<lessonId>/` |
| 播放音轨 | `public/audio/<lessonId>/` |
| 小样、临时渲染结果 | `out/<lessonId>/` |
| 视频、音频、SRT 交付 | `deliverables/<lessonId>/` |
| 讲义记录及最终成果 | `docs/lessons/<章节>/<课时>/handout/` |

- 课时 agent 在本轮授权范围内维护自己的文件。输入稿是内容依据，不因方便制作自行改写用户确认的口播；材料冲突按第五节处理。
- 第六章入口参考 `src/lessons/ch06/L01/index.ts`，由 `src/lessons/ch06/index.ts` 汇总；新章节才需要公共 `src/visual/compositions.tsx` 接入。Composition ID 包含章节和课时，保留所有既有 ID。
- 章节汇总、公共注册、`src/visual/` 公共组件、`contracts/`、共享脚本和配置属于跨课时文件。确需修改时单独说明原因、影响和差异，由整合者审核并统一整合；不要在多个任务里各自重写同一公共组件。
- 第七章继续使用原有注册和编译数据方式；不为了新课统一重写两条制作路线。`current-lesson.json` 仅在自己的工作目录沿用现有行为，不能作为不同任务共用的可写入口。
- 不修改其他课时已审核的内容、配音、修复前备份或成片。其他课时的缺失素材、旧文档问题仅在阻碍本轮目标时处理。

## 四、复用现有导出入口

[共享导出命令和 L01 原命令](../../README.md#共享导出入口阶段-c)已在 README 给出。新课复用 `scripts/render-lesson.mjs`，无需复制整份 L01 导出脚本。

| 参数 | 接手者需要提供 |
| --- | --- |
| `--lesson` / `--composition` | 本课标识与实际注册的 Composition |
| `--audio` | 与所选 Composition 第 0 帧对齐的连续音轨；无声版可省略 |
| `--srt` | 与相同时间轴对应的独立字幕文件 |
| `--output` | 本课输出目录中未使用过的 MP4 文件名 |
| `--frames` | 可选样段范围，如 `240-389`，零起始、两端包含；省略则导出整个入口 |
| `--silent-clean` | 无声版开关；配合支持隐藏口播字幕的 Composition |

有声画面字幕由组件绘制，传入 SRT 用于配套文件；不能给分段 Composition 直接传整课音轨。无声版要求组件支持 `includeAudio=false`、`includeCaptions=false`，或本身不绘制口播字幕；脚本不能自动识别所有文字。教学文字、题面、图解和解析继续保留。

先导出本轮需要的小样。需要重导时使用新版本文件名，不通过删除旧成片绕过防覆盖。共享入口生成视频、配套 SRT 和媒体信息 JSON；独立 WAV 归档及讲义制作需另行完成。

## 五、审核节点与反馈方式

先读项目 [AGENTS.md](../../AGENTS.md)，按需查阅[头尾区域](视频头尾区域规范V0.1.md)、[字幕](字幕规范V0.1.md)、[章节主标题](章节主标题样式规范V0.1.md)规范，以及 [L01 制作总结](../lessons/ch06/L01/第六章-L01-制作与交付工作总结V1.0.md)。沿用已确认规则，不要求重写一套同类文档。

| 节点 | 给用户看的成果 | 通过后继续 |
| --- | --- | --- |
| 内容与画面安排 | 简短分段安排、教材图和真题的关键处理方式；列出会影响制作的材料差异 | 小样制作 |
| 小样 | 有声音和字幕的可观看样段，先确认关键图解、真题或新的布局 | 按确认效果分段制作 |
| 分段 | 本轮完成的内容段、修改点及需要关注的时间位置 | 后续段落或整课组装 |
| 整课与交付 | 可观看整课及四项媒体成果，检查衔接、音量、字幕与答案时序 | 获得用户结论后归档；代码提交按授权执行 |

已通过的小样或段落不重复从头审核；只反馈实际改动及受影响部分。不要直到最终成片才集中暴露问题。

- 真题先核对题干、选项、题号和出处。材料不一致时列出差异，请用户决定未明确的处理方式，先推进不依赖该结论的内容。
- 真题保留独立思考倒计时。读题与倒计时阶段，画面、配音和字幕都不得提前给答案；选项颜色、勾叉、解析文字也不能暗示。答案与对应讲解同步出现。L01 的 3 秒静音倒计时可作为已有参考，新课按确认的安排执行。
- 语音失真、异常停顿或错读：标出具体句子和时间位置，保留修复前素材，局部修复后重新对齐相关字幕及揭示时序，交用户试听。
- 教材图按讲解需要安排在局部或较大内容区；“依据教材重绘”等内部制作说明不进入学生画面。优先沿用自然的半透明选项与解析底板。
- 每次反馈简短写明“完成什么、在哪里看/听、需关注什么、下一步到哪里停止”。遇到确需用户协助的障碍，给出一个最小操作及预期返回结果。
- 静态检查、媒体参数核对和人工视听审核分开记录；只做当前改动需要的验证，不把工具检查称为用户已审核。

## 六、交付、代码与媒体分别保存

| 成果 | 最低交付要求 |
| --- | --- |
| 有声字幕视频 MP4 | 配音、底部口播字幕和教学画面同步 |
| 完整音频 WAV | 与整课视频时间轴对齐，包含约定的思考停顿 |
| 独立 SRT | 使用整课时间轴，不把短样段归零字幕当成整课交付 |
| 无声无口播字幕视频 MP4 | 没有音轨和底部口播字幕；保留教学文字、图形、题面、解析、倒计时；画面帧数与有声版一致 |

媒体放入本课 `deliverables/<lessonId>/`。媒体信息 JSON 是辅助参数记录，不能替代这四项成果。讲义仅在用户要求时制作，先交少量样稿确认清晰度和排版；新课最终放入课时 `handout/`。L01 既有讲义位置保持不动。

审核后的归档步骤：

1. 在该课现有制作记录中注明审核结论、对应文件路径、必要的素材恢复位置及遗留问题；不要把“已生成”写成“已通过”。
2. 获得提交授权后，整合者与课时 agent 核对差异，暂存明确的本课文件及已协调的公共修改，记录 commit。避免用一次不加检查的 `git add .` 带入其他任务改动；上传按用户授权执行。
3. 代码、课程数据、SRT、制作记录和选图 JSON 随 Git 保存；音频、成片、讲义 PDF / 位图及修复前备份单独保存在本地或用户指定的备份位置。核对 `.gitignore`，不通过强制添加把交付媒体传入 Git。
4. 在制作记录中关联代码提交与媒体路径；移交需要的本地素材后再讨论清理工作目录。代码合并不等于媒体已备份，worktree 也不是媒体备份。
