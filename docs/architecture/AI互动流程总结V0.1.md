# AI互动流程总结V0.1

更新日期：2026-11-02。适用于 `course-video-pipeline-codex` 的各课时制作。

按用户已确认的范围推进：分镜方案 → 分组关键帧 → 逐组 Studio 审核 → 集中渲染 → 教学讲义。本流程说明步骤、分工和交付，具体参数与调用方法查对应规范和公共能力索引。

## 一、开工与按需阅读

开工必读：

1. [AGENTS.md](../../AGENTS.md) 与本流程。
2. 本课 `docs/lessons/<章节>/<课时>/input/` 中的口播稿、必读清单，以及清单指定的教材、图表和题目。沿用用户实际目录、输入版本和已确认范围。
3. [公共能力索引](公共能力索引V0.1.md)第一节“使用方式与入口速查”；具体接口用到时再读。

续作时补读本课现有记录中的进度、预览入口、用户审核结论和未完成事项。已经读过且未变化的内容直接沿用，不要求每组重新通读或校准。

| 当前工作 | 补读内容 |
| --- | --- |
| 分镜与画面安排 | [教学画面编排 skill](../../.agents/skills/course-visual-storytelling/SKILL.md)；已有确认安排直接复用 |
| 画面制作 | [视频画面规范V0.2](视频画面规范V0.2.md)，按需读取布局、背景、导航、章节主标题和字幕外观部分 |
| 配音、停顿与字幕时序 | [音频规范V0.2](音频规范V0.2.md)、[字幕规范V0.2](字幕规范V0.2.md)中的适用部分 |
| Studio 预览与导出 | 公共能力索引第九节“现有预览与导出命令”；正式导出时按音频规范核对媒体参数与同步 |
| 独立工作环境或多人协作 | [接手与协作说明](课时制作-Agent接手与协作说明V0.1.md)中第二、三、六节的目录、素材和协作要求 |

项目规范和用户明确要求优先于 skill 的默认建议。链接用于定位当前所需内容，不要求递归通读；历史设计、旧课总结和公共能力更新建议不列为日常制作必读。

口播稿决定讲解顺序和配音正文，未经确认不改写。教材与题目提供概念、关系和答案依据；画面可据此补充必要解释，字幕仍对应口播正文。材料有实质冲突时说明具体差异，由用户确定处理方式，其他不受影响的工作继续推进。

## 二、五个制作步骤

### 1. 建立整课分镜方案

按教学意图划分分镜，用 `S01、S02……` 标识。每镜简要写明口播范围、教学目的、材料依据、画面关系，以及信息进入、强调、保留和退出的安排。画面应帮助学生理解教材中的关系、区别或过程。

方案阶段用口播短语描述时机，实际配音完成后再确定精确时间。交付本课分镜方案，确认后进入分组制作；已有确认内容直接沿用。

### 2. 分镜分组，生成每组关键帧

按讲解完整性和画面连续性组织相邻分镜，在分镜方案中列出组别、镜号范围、主题与关键状态。先确定全课分组，再逐组推进关键帧和视频，使首组反馈能用于后续制作。

每组生成足以说明教学过程的关键帧，数量按需要确定，尽量从实际视频组件导出。关键帧用于检查关系、主次、布局和可读性；视频还需完成中间状态、动态变化与衔接。关键帧随本组迭代，不增加逐镜或逐张审批。

### 3. 分组制作，逐组在 Studio 审核

实现前查公共能力索引，按现有接口通过参数覆盖、组合或局部替换复用组件与方法。确有功能缺口时才新增实现；课时专用逻辑放在本课目录，并继续复用公共能力。

每次完成一个内容组：

1. 落实画面结构，完成本组实际配音、对齐、字幕和教学停顿。
2. 按实际音频与对齐数据安排组件入场、强调、保留、退场和镜间衔接。
3. 自查关键状态与连续播放，检查教学解释、文字可读性、音画配合和观看节奏。
4. 提供可连续播放的浏览器 Studio 链接、Composition、分镜范围和需关注的问题，落实反馈后更新同组预览。**用户预览通过后，才进入下一组制作。**

首组用于确认小样与关键规则，后续沿用，只复核实际改动和受影响部分。配音与对齐在组内完成，不能留到最终渲染才确定。

真题按音频规范第五节执行：中性读题结束后、解析前统一保留 **3 秒真实静音**并同步倒计时；读题与思考阶段不暗示答案，停顿期间清空口播字幕。题目长短不改变这 3 秒，学生可自行暂停阅读。

### 4. 整课组装与集中渲染

所有组通过后，复用已确认画面和配音组装整课，检查组间衔接、全局时间偏移、连续音轨、字幕和倒计时。使用公共能力索引中的现有导出入口；音频格式、双声道、音量处理及同步按音频规范执行，以实际产物核验结果为准。

媒体成果放在 `deliverables/<lessonId>/`：

| 成果 | 要求 |
| --- | --- |
| 有声字幕 MP4 | 配音、口播字幕和教学画面同步 |
| 无声无口播字幕 MP4 | 无音轨、无底部口播字幕，保留教学文字、图形、题面、解析和倒计时；与有声版画面帧数一致 |
| 完整 WAV | 与整课时间轴一致，包含教学停顿 |
| 独立 SRT | 与视频口播字幕同源、同版，使用整课时间轴 |
| JSON 说明 | 记录交付文件、媒体参数、检查结果和待确认事项，沿用现有媒体信息文件按需补充 |

核对文件、版本、媒体参数和时长，复核开头、组间衔接、思考停顿与结尾。技术检查结果与用户视听验收结论分别记录，文件生成不等于已验收。

### 5. 生成教学讲义

依据确认后的课程内容和最终画面，选择解释完整、文字清楚的稳定状态制作讲义。知识页保留理解所需的信息；练习页保留完整中性题面，答案与判断依据放在独立解析页。选帧和裁切依据实际画面状态。

沿用已确认样式；需要新版式时先确认少量页面，再完成整份并检查文字、图示和题目完整性。讲义 PDF、配图及必要选帧记录放在本课 `handout/`，该目录只收纳教学讲义相关成果。

## 三、GPU 分工与命令

Agent 负责方案、代码、预览准备和产物检查，用户负责分组审核与实际视听、阅读验收。需要 GPU 的 TTS、强制对齐、视频渲染和截帧命令交由用户在本机执行，优先使用 RTX 5060 Ti 16GB；Agent 继续处理阅读、编辑和轻量检查，不自行改用 CPU 执行耗时任务。

每次给出当前阶段可直接复制的完整命令，包括工作目录、所需环境、准确的输入输出路径与参数，并说明预期产物和需要反馈的日志。按已具备的素材和代码安排命令；依赖尚未完成步骤的操作，待结果核对后继续。

收到结果后，Agent 检查实际输出、定位报错并继续制作。GPU 是否启用以运行输出为依据；报告渲染耗时时区分浏览器生成画面与 NVENC 编码。
