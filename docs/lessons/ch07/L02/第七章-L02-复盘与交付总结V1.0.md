## 五、五个坑（按严重度排序）

### 坑 1｜cue 的帧号是我手写的（严重：导致整片判卷错位）

- **现象**：旁白还在念选项，画面已经把答案揭开；越往后偏差越大。
- **根因**：L01 用 `findPhrase` 从 token 定位，L02 我图快写成了固定偏移（"S37 起 +15 帧"）。
- **修法**：`scripts/build-l02-cues.ts`——给**原文短语**，在 token 流里找起始时间，换算成相对段起点的帧号，产出 `l02-cues.json`；组件只读数据。
- **校验**：11 条 cue 全部落在目标场景窗口内（脚本自动断言）。
- **教训**：**凡是有音频可查的时间点，都不许手写。** 这已经是第二次同类错误（第一次是把估算时长当交付标准）。

### 坑 2｜四处泄题（严重：直接毁掉题目教学）

| # | 现象 | 根因 |
| :---: | :--- | :--- |
| a | 读题时选项已被划掉 | 无 `eliminate` cue 时，划除时间默认为"时长 42%" |
| b | 双题对决右卡结论条一开始就显示 | `extraNote` 没有跟 `revealed` 绑定 |
| c | 提示条（结论）读题阶段就显示 | tipBanner 在非逐项模式下恒为 `opacity 0.85` |
| d | 题卡副标题直接点破答案 | 我写的 subtitle，如"题干里的…是教材技术可行性分析的原话" |

- **修法**：a/c 改 `ExamQuizCard` 的默认值（划除与揭示同步、tip 默认隐藏）；b 改 `DualQuizBattleCard`；d 改三处文案。
- **教训**：**题卡上任何"结论性文字"都必须绑定揭示状态**——包括副标题这种"看着像标题"的东西。写 payload 时要像审题人一样自问："这句话在揭晓前出现，会不会把答案说了？"

### 坑 3｜`dual-quiz-battle` 的 cue 匹配有隐藏优先级

- **现象**：给左卡的 reveal cue 把右卡也点亮了。
- **根因**：模板里 `rightRevealCue = find(targetId==="right" || action==="reveal-answer")`——任何 reveal cue 都会兜底命中右卡。
- **修法**：左卡改用 `action: "eliminate-option"` + `targetId: "left"`。
- **教训**：复用别人的模板时，**先读它的 cue 匹配顺序**，不要假设"传进去就能按预期工作"。

### 坑 4｜S34 有 27 秒空表

- **现象**：终极防坑表连着 27 秒只有表头和四个空框，像加载失败。
- **根因**：分镜把"立表"和"填表"拆成两镜，但口播在那一段一直在讲四句话，画面无事可做。
- **修法**：S34 改为四句"问法"逐条浮出、归属列留 `?`，S35 再填归属——空屏变成"先摆问题、再给答案"。
- **教训**：**"骨架镜"必须有事发生**，否则观众会以为卡住了。

### 坑 5｜字幕在右引号处断行

- **现象**：`去深入论证一下吧！` / `”这时候，项目就正式迈进了…`——下一行以右引号开头。
- **根因**：clause 切分用正则 `(?<=[。！？；])`，右引号不在回看范围内。
- **修法**：改为手动扫描，标点后把 `”’）》」』】` 一并归入本句。
- **教训**：字幕切分的边界**不是标点，而是"标点 + 其后紧跟的收尾符号"**。

## 六、沉淀成规则（L03 起执行）

1. **时间点一律从 token 派生**，禁止手写帧号；脚本产出 JSON，组件只读。
2. **题卡三段都不得提前泄露答案**：选项态、结论条、副标题——全部绑定 reveal。
3. **复用模板前先读它的 cue 语义**（尤其双卡/多状态模板）。
4. **骨架镜必须有渐进内容**，不能长时间空表。
5. **字幕切分要吃掉收尾符号**（右引号、右括号）。
6. **上线前抽帧核验四件事**：读题前无揭示、揭示点与旁白同步、结论条与揭示同步、静音版无字幕。
7. **改契约后清 webpack 缓存**（`node_modules/.cache/webpack`），否则改动"不生效"。
