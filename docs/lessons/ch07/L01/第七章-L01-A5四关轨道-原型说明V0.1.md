## 二、七个状态与分镜镜号的对应

| # | 状态 | 对应分镜 | 原型时长 | 画面在做什么 |
| :---: | :--- | :--- | ---: | :--- |
| 1 | 建立 | S08 | 3.0 s | 轨道从左向右生长，四座**空门**升起；门下方只有「第一步…第四步」+ 虚线占位条，**不出现名称** |
| 2 | 点亮 | S09 | 7.3 s | 四门依次点亮（每门约 1.6 s），名称与白话注解随门出现——"先立关、再填名"的顺序被强制执行 |
| 3 | 幽灵门 | S10 | 3.3 s | ⑤ 机会可行性研究 从下方滑入 → 两道朱色斜线划叉 → 淡出；右上角警示签 |
| 4 | 盖章 | S12 | 3.0 s | ②③ 之间拉起「可合二为一」虚线；③ 落「★ 不可缺少」金章，③ 门整体转金 |
| 5 | 裁剪 | S13 | 5.0 s | 两条裁剪轨：升级改造（①跳过 ②③保留）、小项目（①②跳过 ③保留）；④ 两行都留「—」并加脚注说明教材未表态 |
| 6 | 推镜 7.1 | S18 | 4.0 s | 相机推近 ① 门（1.55×），其余门压到 18%；底部下三分之一带出「7.1 项目建议与立项申请」 |
| 7 | 交棒 7.2 | S31 | 4.0 s | 相机拉开到 ①②（1.35×），① 落「✓ 批复同意」绿章，② 门顶挂出「7.2 项目可行性研究」 |

合计 **890 帧 ≈ 29.7 s**。分镜里这 7 个镜头实际合计约 111 s，原型只是把"状态演进"压缩演示；接流水线时按镜号给 cue 点即可，几何与状态不用改。

## 三、几何与视觉参数（可直接复用）

| 项 | 值 |
| :--- | :--- |
| 画幅 | 1920×1080 / 30 fps（与项目其余 composition 一致） |
| 门中心 X | 300 / 760 / 1220 / 1680（等距 460） |
| 门尺寸 | 250×200，顶角半径 125（半圆拱），底角 12 |
| 轨道基线 Y | 400（门体垂直中线） |
| 文字层 Y | 步骤 520 / 名称 556 / 白话 600 |
| 裁剪轨 Y | 700、792（行标签在各自上方 34 px，避免与①号芯片相撞） |
| 配色 | **全部取自项目 `colorCard` v1.1 tokens**：`cyan #2EC4D6`、`gold #E0B050`、`red #E0605A`、`green #4CC38A`、`neutral #8FB8D9`、底 `#0B1A33` |
| 动效 | `spring(damping 18, mass .85, stiffness 115)` 用于门体升起；其余用 cubic ease-out，时长 14–34 帧 |
| 背景 | **TechNetwork**（`src/visual/backgrounds/tech-network`，与 MasterCanvas 同参数），挂在 Lab 层；资产组件本身不画背景 |

> **注意**：分镜方案 §2.2 里我给的是一套独立色值（墨蓝 `#0E1626`、金 `#E8B54B`…）。原型落地时改用了项目既有 tokens（`#0B1A33` / `#E0B050`…），因为 A5 最终要放进同一个 MasterCanvas，换色值等于多造一套皮肤。**以本项目 tokens 为准**，分镜那张表按"语义"读，不必按 hex 读。

## 五、做原型时暴露的四个问题（已修）

| # | 问题 | 表现 | 修法 |
| :---: | :--- | :--- | :--- |
| P1 | 相机插值函数参数顺序写反 | 推镜时整块内容被平移到 `x=116154px`，画面**全空**（只剩标题和角标） | `lr(a,b,t)` 统一为 `a+(b-a)*t`；推镜位移回到 240px 量级 |
| P2 | 幽灵门"缩小留证据"与裁剪轨抢位置 | 缩小的 ⑤ 正好压在「② 保留」芯片上 | 改为划叉后**直接淡出**，不留残影；证据交给正片 S16 的回链，不在母版里存 |
| P3 | 裁剪轨行标签与①号芯片重叠 | 「升级改造项目」右端顶到「1 跳过」左缘 | 行标签上移到轨道上方 34 px，芯片仍严格对齐四门 |
| P4 | 推镜时侧卡/页脚与放大后的门打架 | 右侧章节卡盖住 ③ 门，底部文字被放大内容压住 | 侧卡取消，改为**下三分之一字幕带 + 顶部渐变遮罩**；推镜阶段隐去裁剪轨与虚线桥，非焦点门压到 18% |

另外两处是"照着分镜做才发现"的：

- 门在「建立」态必须**只有编号没有名称**，否则 S08 的"留 3 秒让学生意识到有四个位置要填"就失效了。原型里用虚线占位条表达"待填"。
- ③ 的「★ 不可缺少」印章不能放在门体内，会压住编号；放在门框上沿、倾斜 -3°，才既像盖章又不挡信息。

## 六、这次原型还没做的（别当成已完成）

1. **没有接真实口播时长**。每个状态是等长演示，正式版要按 S08—S31 的实际 cue 点驱动。
2. **没有做"进入/退出"两套动画**。现在是单一累计时间线，接流水线时每个镜号要有自己的 entrance，不能靠前一镜残留。
3. **没有做裁剪轨的"逐条拉出"**。S13 是两条规则先后讲，原型是两条同时出现；正式版应按口播分两拍。
4. **没有做 1080p 之外的适配**，也没有做深/浅主题切换。
5. **未接入 `SceneRouter`**。它现在是一个独立 composition，等 S08/S09/S10/S12/S13/S18/S31 的 shot 契约定下来，再把 `stage` 换成 `scene.cue` 字段。
