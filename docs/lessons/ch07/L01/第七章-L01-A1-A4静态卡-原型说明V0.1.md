## 六、接入 SceneRouter（增补）

按"前者"执行：**新增四个独立 visualType**，不借用 `multi-cards` / `process-timeline`。

| 卡 | visualType | payload 契约 |
| :---: | :--- | :--- |
| A1 | `exam-stats` | `ExamStatsPayload`：kicker / title / subtitle / stats[2–4]（value·unit·label·emphasis）/ tags[≤3] / footnote |
| A2 | `chapter-timeline` | `ChapterTimelinePayload`：before / after 两块（kicker·title·note）+ questions[≤3] + conclusion + axisLabel |
| A3 | `four-accounts` | `FourAccountsPayload`：items **固定 4 条**（name·line·tone）+ stamp |
| A4 | `three-steps` | `ThreeStepsPayload`：steps[2–4]（code·verb·full·output·tone）+ footnote |

改动三处：

1. `contracts/visual-props.schema.ts`：新增四组 payload schema + 并入 `VisualSpecUnionSchema`（判别联合从 12 类扩到 16 类）；
2. `src/visual/templates/SceneRouter.tsx`：加四个 `case`，`default` 的 `never` 穷尽检查会自动拦漏；
3. `src/visual/prototypes/Cards14.tsx`：四个组件从"写死数据"改成吃 `payload`，并导出 L01 默认 payload（`L01_EXAM_STATS` / `L01_TIMELINE` / `L01_FOUR_ACCOUNTS` / `L01_THREE_STEPS`）。

**冒烟测试**：`A14Smoke`（composition id 同名）。它**先过 `CompiledSceneSchema.parse()` 再交给 `SceneRouter`**——这一步很关键，它同时验证了三件事：新 payload 合法、`CompiledScene` 的判别联合接受这四个类型、路由命中正确分支。出图在 `out/a14/smoke/`，与 Lab 的出图一致（少一圈评审角标）。

`tsc --noEmit` 通过；`Root.tsx` 里 `CompiledLessonSchema.parse(current-lesson.json)` 也照常通过，老课件未受影响。
