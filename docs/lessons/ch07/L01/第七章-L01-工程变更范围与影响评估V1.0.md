# 第七章 L01｜工程变更范围与影响评估 V1.0

> **评估对象**：`/projects/gaoxiang/course-video-pipeline-Gemini`
> **时间**：2026-10-24 · L01 从分镜到四件套的全过程
> **一句话结论**：**在既有骨架上加宽，不是重构**。数据流未变，但新增了一条绕过编译链的产片旁路，并留下三笔技术债。

---

## 一、判定标准

判断"有没有改架构"，我用三条标准，逐条对照：

| 维度 | 判断 | 依据 |
| :--- | :--- | :--- |
| **数据流** | **未变** | 仍是 `IR → 音频 → link → compiled-lesson → MasterCanvas → SceneRouter → 模板` |
| **契约** | **只增不改** | 判别联合 12 → 19 类，原有 12 类的 schema 与语义一字未动 |
| **目录职责** | **被打破** | `SceneRouter`（生产）开始依赖 `prototypes/`（草稿区）——这是本次唯一的"结构性"变化 |
| **产物结构** | 增加一条旁路 | `L01Film` 不经过 `compile`/`link`，直接手搭时间线 |

## 二、修改的既有文件（6 个）

### 1. `contracts/visual-props.schema.ts`（436 行）

- **改了什么**：新增 7 组 payload schema + 并入判别联合。
  - `exam-stats`（A1 考情卡）
  - `chapter-timeline`（A2 时间轴）
  - `four-accounts`（A3 四笔账）
  - `three-steps`（A4 三件事）
  - `gate-track`（A5 四关轨道，`{ stage 0–6, beatFrames? }`）
  - `id-card`（A8 身份证，`{ stage 0–2 }`）
  - `mnemonic-card`（A9 口诀卡，`{ stage 0–4, cuts? }`）
- **为什么**：把 L01 的视觉资产变成契约里的正式类型，而不是散落在原型里。
- **风险**：低。判别联合是加法，老数据仍可解析。
- **兼容性**：`CompiledLessonSchema.parse(current-lesson.json)` 照常通过。

### 2. `src/visual/templates/SceneRouter.tsx`（64 行）

- **改了什么**：新增 7 个 `case`，`default` 的 `never` 穷尽检查自动兜底。
- **为什么**：让新类型真正能被调度。
- **风险**：低。四处冒烟测试（`A14Smoke` / `A59Smoke`）覆盖。
- **注意**：这里 import 了 `../prototypes/…`——见第六节技术债 ①。

### 3. `src/visual/templates/ExamQuizCard.tsx`（299 → 416 行）

- **改了什么**（六处）：
  1. 逐项判卷（多条 `eliminate-option` 或带 `targetId` 时进入 stepwise）；
  2. 焦点推进：被判选项 1.0、其余 0.28，持续 78 帧；
  3. 思考倒计时环（仅 `thinking-pause` cue）；
  4. `errorHighlight` 红色下划线（该字段此前从未被渲染）；
  5. 提示条改为揭示后才出现（仅 stepwise）；
  6. 组合题不再整行划线，只划被排除的编号。
- **为什么**：A7 真题卡需要"逐项判卷"和"思考留白"，原模板只有"一次性划掉所有错误项"。
- **风险**：**这是唯一一个被修改的共享模板**，风险最高。
- **兼容性证据**：改动前后用老课件 `CourseVideoSilentClean` 同一帧（7952）渲染，PNG **sha256 完全一致**（`ebe975d1…`）。没有逐项 cue 的老场景，一个像素都没变。

### 4. `src/visual/Root.tsx`（71 → 163 行）

- **改了什么**：注册 10 个 composition。现有 11 个：

  `CourseVideo` / `CourseVideoSilentClean`（原有） ·
  `L01Film` / `L01FilmSilent`（成片双版本） ·
  `A5GateTrack` / `A7ExamQuiz` / `A8IdCard` / `A9Mnemonic` / `A14Cards`（资产评审片） ·
  `A14Smoke` / `A59Smoke`（契约路由冒烟）

- **风险**：中。`Root` 直接 `import l01-captions.json`，原型数据进了 bundle（技术债 ③）。

### 5. `src/pipeline/2-audio/srt-exporter.ts`（新增函数，197 行）

- **改了什么**：新增 `buildCaptionsFromNarration(sceneId, narration, tokens, index)`。
- **为什么**：对齐 token **不是逐字的**——数字会被合并（`2.68%，2026` → `2682026`）、标点被丢弃。只按字数切，必然切出"…三个身份信"这种半句。
- **做法**：原文按标点切 clause → 每 clause 归一化后在 token 流里顺序查找 → 命中段落的首末 token 即该句时间 → 合并成行（标点优先，字数兜底）→ 超长再按「：；，、」二次切。
- **风险**：低。旧函数 `buildCaptionsFromTokens` 保留未删。

### 6. `src/pipeline/2-audio/audio-runner.ts`（259 行）

- **改了什么**：两处调用从 `buildCaptionsFromTokens` 切到 `buildCaptionsFromNarration`。
- **风险**：**行为变更**——未来所有章节（L02/L03…）的字幕切分都会改变。这是有意的改进，但不是纯增量，需要知道。

## 六、三笔技术债

### ① `SceneRouter` 依赖 `prototypes/`（建议优先修）

- **现象**：生产路由 import 了草稿区的 7 个组件。
- **影响**：目录语义失效；将来清理 `prototypes` 会直接打断产线。
- **修法**：把 `GateTrack` / `IdCard` / `Mnemonic` / `Cards14` / `scene-adapters` 挪进 `templates/`，`prototypes/` 只留 Lab、冒烟与时间线数据。
- **成本**：约 1 小时，纯移动 + 改 import，无逻辑变更。

### ② `L01Film` 是绕过编译链的第二条产片路径（需要决策）

- **现象**：`IR → compile → link → MasterCanvas` 是一条路；`L01Film` 手搭时间线是另一条。
- **影响**：两条路并存 ⇒ 后面每章都可能被要求"手搭一条"，产能不可复制。
- **取舍**：走编译链要接受"一镜一场景"，A5 这类跨镜状态机会失去连续演进；保留旁路则要维护两套时间线。
- **建议**：**L02 先走编译链验证一次**，再决定要不要保留旁路。

### ③ `Root` 直接 import 原型数据（建议随手修）

- **现象**：`Root.tsx` import 了 `l01-captions.json`。
- **影响**：换章要改代码；原型数据进 bundle。
- **修法**：`L01Film` 改为吃 `--props`（`captions` / `audioSrc`），或走 `compiled-lesson.captions`。
- **成本**：约 30 分钟。

## 七、建议清单

| 优先级 | 建议 | 理由 |
| :---: | :--- | :--- |
| **P0** | 把 7 个组件从 `prototypes/` 挪进 `templates/` | 唯一的"架构级"缺陷，且修复成本极低 |
| **P0** | `Root` 的 composition 改为吃 props，不 import 章节数据 | 否则每加一章都要动 Root |
| **P1** | 给 `visual-transpiler.ts` 补这 7 类的抽取规则（或改由结构化输入） | 否则 `npm run compile` 永远产不出这些类型，编译链对 L01 是"半通" |
| **P1** | 决定旁路去留（第二节 ②） | 影响 L02 之后所有章节的做法 |
| **P2** | 字幕切分加"语义完整性"判断 | 现在是启发式，长句仍可能切在语义中途 |
| **P3** | 把 `scripts/` 收成 npm scripts 或 Makefile | 换章只需改参数 |

## 七之二、P0 修复记录（2026-10-25 已完成）

按第七节清单，两条 P0 均已修完并验证。

### P0-1：把组件从 `prototypes/` 挪进 `templates/`

做法不是整文件搬，而是**拆开**——组件归 `templates/`，评审用的 Lab 归 `prototypes/`：

`SceneRouter` 现在只依赖 `./Cards14` 与 `./scene-adapters`，**不再 import 任何 `prototypes/` 路径**。

### P0-2：`Root` 不再 import 章节数据

- `Root.tsx` 现在只 import **组件模块**及其导出的常量（如 `A5_STAGES`），不再 import `l01-generated`、`l01-captions.json` 一类数据模块；

- `L01Film` 新增两个可选 props：`audioSrc`（配音轨路径）与 `captions`（字幕数组），缺省用本章内置值。换章时可以走 `--props` 注入，不必改代码。

## 八、结论

**这次没有重构，是在既有骨架上加宽。** 真正被改的共享件只有 `ExamQuizCard` 一个，且用逐像素回归证明了零影响。

但有两件事必须承认：

1. **目录职责被打破了一次**（生产依赖草稿），这是"加宽"时最容易留下的隐伤，修起来却最快；
2. **多了一条旁路**，它不是架构变更，却会改变以后每章的做法——这是需要你拍板、而不是我自行决定的。
